# 2.6 Valuation

**Status:** ⬜ not started · **Epic:** P2 E08 · **Spec:** VAL01–VAL03, §3.3 money as decimals with currency, §14.2 `valuation_rates` (2.2), loss line `valuation snapshot`, D08 · **Tests:** T38 T45 · **Depends on:** 2.2, 2.5

## Goal
Value every loss line with an effective-dated, versioned rate (contribution margin, standard cost or cost per hour) and record a complete valuation snapshot, so financial impact is reproducible, never fabricated (no flat $100/unit), and never double-counted across bases or currencies.

## Spec requirements covered
- VAL01 value by effective-dated product margin or standard cost with currency and unit; GE-style selectable margin versions on profiles; default commercial view = contribution margin; standard cost separately named; neither is realized saving; financial policy approval recorded before production use.
- VAL02 duration cost = `seconds / 3600 × cost_per_hour`; quantity-based and time-based valuations are **alternative** bases for the same loss unless categories are independent cost components; never add lost margin to a downtime rate that includes it.
- VAL03 snapshot rate version, currency, FX version, valuation date, basis, quantity, rounding; never aggregate currencies without approved conversion snapshot; missing price → unvalued quantity, **null cost**; round only presentation totals.

## Current implementation (verified)
- Browser: `Total Loss Value = Σlosses × lossValuePerUnit (100)`, event cost auto-fill (product `standardCost` or impact code rate with duration treated as hours), severity-based `$/h` fallback in `UnifiedAnalyticsService`; `production_events.cost` free input; `impact_codes.cost_per_unit/cost_per_hour/cost_basis` stored; `products.standard_rate` ambiguous. No currency anywhere.

## Target design
**Schema (migration `0014-valuation`)**
```
valuation_policies (accounting_policies kind=valuation_basis): tenant/site scope, default_basis enum(contribution_margin, standard_cost), time_basis_rule enum(exclusive, independent_components), currency char(3), fx_policy enum(none, snapshot), approved_by/at, version
fx_rate_snapshots: id, tenant_id, from_ccy, to_ccy, rate numeric(24,10), as_of, source, version
loss_lines.valuation jsonb -> {basis, rateVersionId, unitValue, currency, fxVersionId|null, valuationDate, quantity|seconds, amount|null, status: valued|unvalued|mixed, roundingPolicy}
loss_line_valuations (normalized copy for querying): id, loss_line_id, basis, rate_version_id, currency, amount numeric(24,8) null, status, valuation_date
```
**Service** `ValuationService.value(run)` (called by 2.5 inside the run):
- For each active loss line: pick rate by `basis` from `valuation_rates` effective at `valuationDate = segment_start` for the slice's profile (quantity bases) or the impact code (cost per hour, time basis); `amount = quantity × unitValue` or `seconds/3600 × costPerHour`; no rate → `amount null`, `status unvalued` (T38).
- **Exclusivity (VAL02)**: a line is valued on one basis per view; reports expose `commercialOpportunity` (margin) and `standardCostView` and `operationalCost` (time) as **separate** totals; the `independent_components` rule allows summing only when policy marks the impact category as an independent cost component.
- Multi-currency (T45): totals grouped by currency; combined total only when `fx_policy=snapshot` and a snapshot exists for the valuation date → `fxVersionId` recorded; otherwise `combinedTotal: null, reason: 'fx_missing'`.
- Rounding: store 8 dp; API returns decimal strings; presentation rounding to currency minor units in the frontend/export layer only.
- Gains and residuals are valued but labelled; never netted into "savings".

**Legacy bridge**: `impact_codes.cost_per_hour/cost_per_unit` migrated into `valuation_rates(impact_code_id, basis=cost_per_hour|standard_cost)` with `state=draft` until finance approves (D08); `products.standard_rate` → `valuation_rates(profile, basis=standard_cost, state=draft)` after owner confirmation (MIG §18.2); the browser `lossValuePerUnit` is removed in 3.5.

**API v2**: valuation appears on `GET /production-periods/{id}` lines and totals; `GET /reports/loss-tree?metric=margin|standard_cost|operational_cost`; `GET/POST /fx-rate-snapshots`; `POST /valuation-policies/{id}/approve`.

## Tests
- **T38 missing price**: loss 25 t with no effective margin → quantity 25, `amount null`, `status unvalued`; totals show `unvaluedQuantity 25`.
- **T45 multi-currency**: lines in EUR and USD, no FX snapshot → separate totals, `combinedTotal null`; with snapshot → combined with `fxVersionId`.
- VAL02: availability line valued as margin 2,500 and as time cost 1,200 → report shows both views, never 3,700; `independent_components` policy on an impact category allows summation only for that category.
- Rate effective-dating: rate change at 10:30 → line 10:00–10:30 uses v1, 10:30–11:00 uses v2.
- Rounding: 8-dp storage; API string `"1234.56780000"`; export rounds to 2 dp but totals computed from unrounded values.
- No valuation runs before policy approval → `status unvalued`, reason `policy_unapproved`.
