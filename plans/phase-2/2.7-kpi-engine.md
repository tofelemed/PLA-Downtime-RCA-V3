# 2.7 KPI engine — operational OEE, reconciled OEE, downtime and reliability measures

**Status:** ⬜ not started · **Epic:** P2 E08 · **Spec:** KPI01–KPI08, AN03 aggregation, §14.2 `kpi_results`, D04 D13 · **Tests:** T20 T21 T31 T41 · **Depends on:** 2.1, 2.4, 2.5

## Goal
Compute every KPI on the server from schedule, state, actuals and loss-line data inside the calculation run, with explicit numerators and denominators, null-with-reason on missing denominators, ideal-time weighting across products, and clear labels distinguishing operational OEE from the GE-style reconciled OEE and MTTR from mean-downtime-to-restore.

## Spec requirements covered
- KPI01 S planned seconds after calendar exclusions; D union availability-stop seconds within S; R = S − D; U ideal time for gross; V ideal time for good; A = R/S, P = U/R, Q = V/U, OEE = V/S; ideal-time weighting across products/rates; stream boundaries for concurrent streams.
- KPI02 micro-stops stay in R and reduce P; availability stops don't double-penalize; planned stops inside S reduce A; exclusions outside S reduce utilization not OEE; unknown intervals → provisional/unavailable per coverage policy, never treated as running.
- KPI03 zero/missing denominators → null with reason; factors > 100 % preserved as exceptions; **no calculation from a page render; reads side-effect free**.
- KPI04 reconciled PLA OEE from G, LA, LP, LQ; labelled; idle/no-planned-production disclosed separately.
- KPI05 total/planned/unplanned/micro/unknown downtime, stop count, mean stop, scheduled availability, onstream factor (own denominator).
- KPI06 stop count by occurrence start in window; carry-in separately; splits don't inflate; mean completed-stop duration cohort labelled; trend uses clipped duration.
- KPI07 MTBF = operating exposure / eligible failures starting in window per repairable asset and taxonomy; none → null with exposure and count; coverage reported; slowdowns/planned/micro/advisory are not failures.
- KPI08 MTTR requires active repair evidence; otherwise label **mean downtime to restore**; open repairs censored.
- AN03 aggregations from summed numerators/denominators; site-local grouping; cross-site comparisons show tz/unit/mode/product/policy/coverage/baseline.

## Current implementation (verified)
- Three browser OEEs: Plan Dashboard arithmetic (P = output/plan, not ideal time; writes to `oee_summaries` on render), `UnifiedAnalyticsService` heuristic (constant 87 % with no data), `DashboardAnalytics` duplicate. Reporting averages `oee_summaries` percentages (mean of %). No MTBF/MTTR; downtime sums assume minutes.

## Target design
**Schema (migration `0015-kpis`)**
```
kpi_results: id, tenant_id, run_id, scope jsonb {unitId, sliceId|null, productId|null, assetId|null}, metric enum(availability, performance, quality, oee, reconciled_availability, reconciled_performance, reconciled_quality, reconciled_oee, downtime_total, downtime_planned, downtime_unplanned, microstop_time, unknown_time, stop_count, carry_in_count, mean_stop_duration, scheduled_availability, onstream_factor, mtbf, mttr, mean_downtime_to_restore, coverage),
  policy_id, numerator numeric(24,8) null, denominator numeric(24,8) null, value numeric(24,10) null, unit, quality enum(ok, provisional, unavailable, exception), reason text null, cohort jsonb null, as_of
  INDEX (tenant_id, run_id, metric)
failure_events (view/derived): eligible functional failures per D13 taxonomy (FailureWO events or unplanned stops with failure codes), asset_id, start, repair_start null, restored_at null, source
```
**Engine** `src/domain/kpi/` (pure decimal):
- `operationalOee(inputs)`: `S = scheduledSeconds (2.1) − excluded`; `D = union(availability occurrences ∩ S)` (1.1 union; planned stops inside S included per policy); `R = S − D`; for each product/rate segment `U_i = gross_i / sustainedRatePerSec_i`, `V_i = good_i / sustainedRatePerSec_i` (ideal-time weighting); `A = R/S`, `P = ΣU/R`, `Q = ΣV/ΣU`, `OEE = ΣV/S`. Micro-stop/slowdown time stays in R (KPI02). Unknown segments: if `unknown_time / S > policy.maxUnknownShare` → `quality=provisional|unavailable` with reason. Zero S or missing good/gross → `value null`, `reason` (`no_scheduled_time`, `quality_evidence_missing`, `no_profile`). Factors > 1 kept, `quality=exception`.
- `reconciledOee(G, LA, LP, LQ)`: formulas from KPI04; requires fully declared loss basis (all active capacity lines classified) else `unavailable`; idle/no-planned-production reported as separate quantities.
- `downtimeMeasures(occurrences, segments, window)`: totals by `schedule_class`, micro-stop time, unknown time; `stop_count` = occurrences with start ∈ window (occurrence, not events → splits don't count); `carry_in_count`; `mean_stop_duration` over occurrences **ending** in window (full duration, cohort labelled); `scheduled_availability = R/S`; `onstream_factor = (calendarSeconds − totalDowntime)/calendarSeconds` with named calendar denominator.
- `reliability(failures, exposure)`: `mtbf = operatingSeconds / failuresStartingInWindow` per asset, null when 0 failures (with exposure and count); `mttr` only when `repair_start/restored_at` evidence exists for completed repairs (Σ active repair / count; open censored); else `mean_downtime_to_restore = Σ outage duration / count`, labelled.
- `aggregate(results[])`: sum numerators/denominators then divide (T31); refuses to combine incompatible denominators (different S policies or stream boundaries) → `unavailable` with reason; groupings by shift/day/week/month via `shift_instances` local labels.

**Run integration**: 2.5 run computes `kpi_results` for period scope; report endpoints (3.6/3.3) aggregate across periods by summing stored numerators/denominators, bound to run ids; no on-read computation that writes.

**Compatibility**: view `oee_summaries_v` from `kpi_results` (A/P/Q/OEE per period) for v1 Reports until 3.6; `POST/PUT /oee-summaries` returns 410 once 3.5 removes the browser write.

**API v2**: `GET /reports/oee?unitIds&from&to&groupBy&policy=operational|reconciled&approvedOnly`, `GET /reports/downtime?groupBy=reason|reasonLevel1|impact|oee|asset|shift|crew|day|week|month&metric=duration|frequency&scheduleClass`, `GET /reports/reliability?assetIds&from&to` — each returns `calculationRunIds[]`, `policyVersion`, `coverage`, `isProvisional`, numerators/denominators (API03).
