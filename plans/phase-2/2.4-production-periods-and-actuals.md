# 2.4 Production periods and actuals results

**Status:** ⬜ not started · **Epic:** P2 E08 · **Spec:** ACT01–ACT08, §3.1 reporting grain, §14.2 `production_periods`, `period_product_slices`, `actuals_results`, `external_production_reports`, SRC01 (consumer), D05 · **Tests:** T25 T26 T27 (persisted), T12, T44 · **Depends on:** 2.1, 2.3, 1.7, 1.10

## Goal
Create the accounting grain — one production period per unit per calendar leaf with product slices — and compute authoritative actuals (gross, good, rejects, rework) per slice from the selected source with coverage and quality, plus governed manual adjustments and the external daily-production (Maximo) record, keeping actuals revisions separate from loss-explanation revisions.

## Spec requirements covered
- ACT01 slice records gross/good/reject/rework, method, source segments, coverage, quality, revision; good = accepted at accounting boundary; inventory movements are not production without a mass-balance policy.
- ACT02 output events counted once; spanning events need measured distribution or approved proportional estimate marked Estimated; counter deltas with splits; no negative delta.
- ACT03/ACT04 engine rules (implemented in 1.7) applied per period with persisted method and excluded bad intervals.
- ACT05 `coverageRatio`, `measuredQuantity`, `estimatedQuantity`, quality flags; missing = null not zero; approval needs 100 % accepted coverage (approved substitutions count, estimated share exposed) unless a versioned policy says otherwise.
- ACT06 manual actuals/corrections need reason, evidence, unit, author, window, independent approval when affecting approved reports; raw immutable; daily-production revision ≠ PLA explanation revision (T44).
- ACT07 rejects once; rework → good only when accepted and not double counted; gross vs good basis declared; never invent 100 % quality.
- ACT08 external daily-production record (externalReportId, revision, site, local date, tz, UTC boundaries, lines, basis, status, approvedAt, evidence); status mapping to certified eligibility; dedupe by report id + revision; later revision = correction candidate.
- §3.1 never count both shift and daily rows; campaigns split periods; concurrent products = separate slices with explicit shared-capacity model.

## Current implementation (verified)
- `production_losses.actual` typed by user or synced from Σ ProductionOutput event quantities on a button; `oee_summaries` time columns not writable; no period entity; no coverage; no external report import; `reconcile_forms`/plans mix actuals and explanations.

## Target design
**Schema (migration `0012-periods-actuals`)**
```

  UNIQUE (tenant_id, unit_id, utc_start)

  method enum(output_events, counter_delta, rate_integration, manual, external_report, mixed), coverage_ratio numeric(9,8), measured_qty, estimated_qty, quality_state enum(complete, partial, missing, conflict),
  source_segments jsonb [{signalId|source, from, to, qty, method, quality}], exceptions jsonb, computed_at
```

**Period lifecycle (worker)**
- `PeriodMaterializer`: at each shift end (and on demand/backfill) create `production_periods` from `shift_instances` for units with an approved profile; slices from the accounting-baseline plan version's `plan_periods` (campaign-aware) or from the profile's default product when no plan.
- `ActualsRunner.run(periodId)`: for each slice resolve authority (1.10) → `method`; compute via 1.7 engine within `[utc_start, utc_end)`:
  - `output_events`: Σ `production_output` events with timestamp in window, once per source identity; spanning events: measured distribution from attributes if present, else proportional-time estimate marked `estimated` (policy `coverage_gate.allowProportionalEstimate`).
  - `counter_delta` / `rate_integration`: engine result incl. exceptions → `quality_state`.
  - `external_report`: if policy says certified external record is authority, take line quantities when `certified_eligible`.
  - rejects/rework per ACT07; `good = gross − reject + rework_accepted` when basis gross; if only good known → `gross null`, quality factor unavailable (never 100 %).
  - approved `actuals_adjustments` applied as separate component with `estimated` share.
  - coverage = observed/accepted seconds ÷ window; `quality_state` from exceptions; result immutable per run.
- Triggers: `Normalized` samples/events in window, authority change, adjustment approval, external report import → `PeriodRecalculateRequested` (consumed by 2.5 which calls `ActualsRunner` inside its run so actuals and losses share one run).
- **Separation (ACT06/T44)**: actuals changes create a new *actuals* result in a new run; loss-explanation changes (2.8 draft lines) reuse the current actuals result without recomputing it unless inputs changed; both referenced by the accounting revision.

**API v2**: `GET /production-periods?unitIds&productIds&from&to&readiness&workflowState` (grid with authoritative summaries), `GET /production-periods/{id}` (slices, actuals with provenance), `POST /actuals/adjustments`, `POST /actuals/adjustments/{id}/approve|reject`, `POST /external-production-reports` (import; 202 job for files), `POST /production-periods/{id}/recompute` (202).

## Tests
- **T25/T26/T27 persisted**: periods with rate, rollover and unresolved-reset signals produce `actuals_results` with method, `60 t`, `10`, and `null + exception` respectively; coverage reflects gaps.
- **T12**: PI output EF and MQTT counter both present → one method chosen per policy; conflict recorded; gross not doubled.
- **T44 manual actuals**: approve a period (2.8), then change loss explanation → new accounting revision referencing the **same** actuals result; approve an actuals adjustment → new actuals result and separate revision; daily-production certified value unchanged by explanation edits.
- Spanning output event across two shifts without distribution attribute → proportional split marked `estimated`; with policy disallowing → `quality_state partial`.
- Missing samples for 10 % of window → `coverage_ratio 0.9`, `measured_qty` only; approval gate (2.8) blocks.
- External report revision 2 for same id → previous marked superseded; quantities not summed.
- Only-good-known import → `gross null`, quality factor unavailable in 2.7.

## Definition of done
- Periods materialize per shift; actuals computed per slice with method, coverage and provenance; adjustments governed; external reports imported as corrections; T12 T25–T27 T44 green; v1 Plan Dashboard reads periods via compatibility view.

## Decisions / risks
- D05 decides authority and gross/good boundary per product; defaults: output EFs primary, counters fallback, basis gross.
- D03 daily-leaf sites: periods are daily; `shift_name` null.
- Mass-balance from tank levels is explicitly out unless a policy exists (ACT01) — not planned for R1.
