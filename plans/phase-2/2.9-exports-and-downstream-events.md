# 2.9 Exports, domain events and downstream delivery

**Status:** ⬜ not started · **Epic:** P2 E09 (immutable exports) + §15.4 · **Spec:** API04 jobs, API05 realtime/domain events, §15.2 `/exports`, `/jobs/{id}`, §14.2 `export_jobs`, `inbox/outbox`, WF03 downstream after commit, AN03 CSV/PDF exports, ACT08 Maximo exchange (draft), D12 · **Tests:** T39 (with 3.12 restore), API04 count reconciliation, API05 once-per-outbox-id · **Depends on:** 2.8, 1.9

## Goal
Deliver approved (or explicitly provisional) results outward in three ways — immutable report exports bound to a result snapshot, versioned domain events on Kafka for realtime and integration consumers, and downstream deliveries (data lake, CMMS) with receipts — all after commit, idempotent, authorized and auditable.

## Spec requirements covered
- API04: replay/recompute/import/export return 202 + job id; status exposes accepted/processed/quarantined/rejected/pending; cancellation preserves committed outcomes, declares partial; cancelled export not downloadable.
- API05: scoped subscriptions; notifications carry entity id, revision, type, occurredAt, scope (no raw data); per-scope sequence for resync; emit once per outbox id; clients dedupe.
- §15.4 domain messages: EventChanged, SourceHealthChanged, PeriodCalculationCompleted, PeriodSubmitted, PeriodApproved, PeriodRestated, MappingExceptionRaised, RCARecommended with `schemaVersion, domainEventId, tenantId, entityId, entityRevision, occurredAt, correlationId`; PeriodApproved/Restated include revision id, prior revision, product totals, quality, unit/currency, policy.
- §15.2 `POST /exports {report filters, format, revision selector}` → export job bound to snapshot; `GET /jobs/{id}`; `export_jobs` reauthorize download; immutable content.
- AN03 CSV and PDF with filters, generated time, approved/provisional status, calculation revision.
- WF03 downstream only after commit through outbox; delivery failure cannot undo approval.
- ACT08/§10.1: external daily-production exchange format; exported PLA revisions include source daily-report references; email export only as explicit adapter.
- NFR02 CSV formula-leading string sanitization.

## Current implementation (verified)
- Reports page exports JSON client-side; Event Hub CSV built in browser (no sanitization). No export jobs, no domain event schema, no downstream delivery. Realtime gateway broadcasts raw entities to all clients. `integration/cmms/push` stub.

## Target design
**Schema (migration `0017-exports-delivery`)**
```
export_jobs: id, tenant_id, requester_id, report_type, filters jsonb, revision_selector enum(approved, latest_draft, run_ids), run_ids uuid[], format enum(csv, pdf, json), state enum(queued, running, completed, failed, cancelled), object_ref, content_hash, size, row_count, generated_at, expires_at, download_count
  -- content immutable after completed; download requires fresh authz check
jobs (generic): id, tenant_id, kind enum(export, replay, recompute, import, bulk_code, backfill), state, counts jsonb {accepted, processed, quarantined, rejected, pending}, error, requested_by, created_at, started/finished_at, cancel_requested bool, partial bool
downstream_deliveries: id, tenant_id, outbox_id, target enum(data_lake_webhook, kafka_topic, cmms, email_adapter), state enum(pending, delivered, failed, dead), attempts, last_error, receipt jsonb, delivered_at
realtime_sequences: scope_key text PK (tenant:site:unit), seq bigint
```
**Domain event contracts** `contracts/domain-events/*.schema.json` (one per message type, versioned `v1`), TypeScript types generated; `OutboxRelay` validates payloads against schema before publishing; `PeriodApproved` payload built from `approval_snapshots` (totals per product, quality, uom/currency, policy versions, prior revision).

**Export worker**: consumes `export` jobs; loads the exact result version (`run_ids` resolved at job creation from `revision_selector`, so later recalcs don't change content); renders CSV (RFC 4180, UTF-8 BOM optional, **formula-leading `=+-@` prefixed with `'`**, decimal strings, explicit units) or PDF (headless Chromium via Playwright already in repo, or `pdfkit`) with header block: scope, filters, timezone, generated at, approved/provisional, calculation run ids, policy versions; stores to object store (`uploads/exports/` volume or MinIO) with sha256 `content_hash`; job `completed`; cancellation before completion → `cancelled`, object deleted, download 410.

**Downstream delivery worker**: consumes `pla.period.approved.v1` (and `PeriodRestated`) via inbox; for each configured target creates `downstream_deliveries`; webhook delivery with HMAC signature and idempotency header = `outbox_id`; Kafka external topic republish; CMMS/Maximo adapter R1 = draft payload format + stub endpoint returning `not_configured` (D12); exponential retry → `dead` + alarm; receipts stored; **reconciliation report** endpoint lists approved revisions vs delivered receipts.

**Realtime notifications**: gateway consumer (transport from 1.9) maps domain events to room notifications `{entityId, revision, type, occurredAt, scope, seq}`; `seq` from `realtime_sequences` per scope (atomic increment in outbox transaction); clients resync via `GET …?sinceSeq=` or snapshot refetch (rooms/auth completed in 3.1).

**Maximo/daily-production exchange (draft)**: `contracts/external-production-report.schema.json` (import, consumed by 2.4) and `contracts/pla-revision-export.schema.json` (export with `sourceDailyReportIds[]`), documented for D12; no live connection in R1.

**API v2**: `POST /exports` → 202 `{jobId}`; `GET /jobs/{id}`; `POST /jobs/{id}/cancel`; `GET /exports/{id}/download` (reauthorized, streams object); `GET /deliveries?revisionId`; `GET /deliveries/reconciliation?from&to`.

## Tests
- **T39 export and restore** (with 3.12): approve + export → hash H; restore backup; replay outbox → same approved totals and hash; downstream receives idempotent delivery (second delivery acknowledged as duplicate by `outbox_id`).
- API04: export job over N rows → counts reconcile (`processed + quarantined == accepted`); cancel mid-run → `cancelled`, download 410, partial flag; status endpoint authorized by tenant.
- API05: relay retry → one Kafka record per `domainEventId`; consumer dedupe; `seq` strictly increasing per scope; `sinceSeq` resync returns gap.
- Export content: CSV cell `=HYPERLINK(...)` sanitized; decimals as strings; header shows approved vs provisional and run ids; recalculation after job creation does not alter file (hash stable).
- Delivery: webhook 500 ×3 → retries with backoff → `dead` + alarm; approval row unchanged.
- Download requires valid token and scope at download time (expired/foreign → 403).

## Definition of done
- Exports are immutable, snapshot-bound, sanitized, cancellable; domain events schema-validated and emitted once; downstream deliveries tracked with receipts and reconciliation; realtime sequence available; T39 (export half) and API04/05 tests green.
