# 3.10 Migration and cutover

**Status:** ⬜ not started · **Epic:** P3 E12 Production readiness · **Spec:** MIG01–MIG06, §18.2 remediation table, §14.3 compatibility views and crosswalk, D11 · **Tests:** before/after migration report; MIG04 reconciliation; rollback rehearsal · **Depends on:** all 3.x feature sub-phases (flags available)

## Goal
Move existing data into the new model without loss or invention, run the new accounting beside the old reports on a pilot scope, prove the differences are explained, then switch writes by feature flag with a rehearsed rollback — never deleting accepted source records.

## Spec requirements covered
- MIG01 baseline verified (0.1); MIG02 expand-and-contract with compatibility adapters, staged backfill, compare/approve, flag switch, retire after gates; immutable backups; legacy-ID mapping.
- §18.2 remediation rules: mixed duration units; year-9999 sentinel; duplicate source events; missing tenant/invalid refs; free-text periods; unpersisted hierarchy; client-entered loss/OEE (`UnknownLegacy`); missing event-to-loss links; ambiguous `standard_rate`; flat currency/MT.
- MIG03 pilot one unit/product with PI, then MQTT/Kafka; ≥ 2 operational weeks incl. month-end; coverage is the criterion.
- MIG04 compare source counts, intervals, actuals, plan sums, loss conservation, valuation, exports; differences explained, no balancing adjustments; epsilon rule.
- MIG05 freeze → drain → snapshot → final delta → verify → activate v2 → resume; legacy views read-only; rollback via flags; never roll back by deleting source records.
- MIG06 release prerequisites (connector certification, isolation tests, fixtures, migration reconciliation, restore drill, runbooks, training, acceptance).

## Current implementation (verified)
- Demo data only (1 unit, 6 users) at the time of writing — but MIG01 forbids assuming that; the pilot site's real data state is unknown. Legacy tables: `production_events` (expanded in 1.1), `production_losses`, `reconcile_forms`, `loss_categories`, `oee_summaries`, `source_hierarchy_mappings`, `af_bindings`, `pi_sync_jobs/watermarks`, `pi_events`, `unmapped_events`, `rca_trigger_configs`.

## Target design
**Remediation jobs** (worker commands, idempotent, each writes a report row to `migration_reports`):
| Legacy issue | Job | Behaviour |
|---|---|---|
| Mixed durations | `remediate:durations` | recompute from start/end; infer only where source/seeder contract documented minutes (`legacy_duration_unit_assumed`); else quarantine (`migration_review`) |
| 9999 sentinel | `remediate:sentinels` | end → null, raw kept (done in 1.1 backfill; re-verified) |
| Duplicate source events | `remediate:duplicates` | group by tenant/connection/source identity; compare facts + edits; canonical chosen, `merged_from` lineage; conflicting edits → review |
| Missing tenant / bad refs | `remediate:references` | resolve from ownership evidence (unit→tenant); unresolved → quarantine; never default tenant |
| Free-text periods | `remediate:periods` | parse `production_losses.period` with plan context + tenant tz → candidate `production_periods`; ambiguous → review |
| Unpersisted hierarchy | `remediate:reason-tree` | import approved tree file if provided; else flat codes; no invented parents |
| Client-entered loss/OEE | `remediate:legacy-values` | copy into `legacy_reported_values(method='UnknownLegacy')`; never labelled recalculated/approved |
| Missing event↔loss links | `remediate:links` | reconstruct only from explicit legacy ids (`reconcile_forms.productionEvent` when a valid id); else unlinked explanation with provenance |
| `standard_rate` | `remediate:rates` | after D08 confirmation split into `valuation_rates`/`unit_product_rates`; before: flagged |
| Currency/MT | `remediate:units` | require uom/currency mapping table; unresolved rows flagged |
`legacy_id_crosswalk(legacy_table, legacy_id, new_table, new_id)` maintained by every job.

**Parallel run** (pilot scope): flags keep v1 screens; v2 computes periods/runs for the pilot unit; `GET /migration/compare?unitId&from&to` produces the MIG04 comparison (source counts, intervals, actuals, plan sums, loss conservation, valuation, exports) with explanations captured per difference (formula change / quality change / defect) — no balancing adjustments permitted (lint on `loss_lines.kind='bridge'` created by migration = forbidden).

**Cutover runbook** (MIG05, scripted `scripts/cutover/*.ts` with dry-run): freeze legacy writes (v1 write routes → 423 for scope) → drain ingestion jobs → snapshot offsets/DB → final delta remediation → verify counts/totals → flip `v2.*` flags for scope → resume collectors; rollback = flip flags back (v1 reads via compatibility views remain), buffered source data retained for replay.

**Retirement** (contract phase, later release): drop legacy write paths and tables only after two clean reconciliation cycles; compatibility views stay read-only.

## Tests
- Each remediation job: fixture DB → expected rows/flags; idempotent re-run no change; never writes default tenant; quarantine counts reported.
- Comparison: seeded divergence (formula change) is listed with explanation slot; unexplained delta > epsilon fails the gate.
- Cutover dry-run on staging: counts/totals match; rollback restores v1 serving; no source rows deleted (row-count assertion).
- Legacy write freeze returns 423 with pointer; collectors resume with bounded overlap (no gaps, duplicates recognised).

## Definition of done
- All remediation jobs run with reports; parallel run completed on pilot with explained differences; cutover rehearsed and executed for pilot scope; rollback proven; crosswalk complete.

## Decisions / risks

- The real pilot site may have data this repo has never seen; jobs must be defensive and report rather than fail.
