# 3.11 Security, tenant isolation and performance

**Status:** 🔄 in progress (implemented and tested 10 Oct 2026: JWT hardening, RLS policies + binding **on**, isolation fixes, token-protected uploads, limits, secrets, dependency fixes, perf pass; open: T40 soak / staging, Lighthouse / k6 / compression, Redis — owner / host items) · **Epic:** P3 E12 · **Spec:** NFR01–NFR03, WF05, §17.1 targets, §4.2 trust boundaries, T14 (all interfaces), T40; [ENGINEERING_STANDARDS.md](../ENGINEERING_STANDARDS.md) · **Tests:** T14 full matrix; T40 load/soak; security test summary · **Depends on:** 3.1–3.9

## Goal
Prove, with tests and measurements, that the platform isolates tenants on every interface, authenticates through SSO with scoped short-lived tokens, protects secrets and payloads, and meets the agreed latency/throughput objectives under load with a worker restart — before any production release.

## Spec requirements covered
- NFR01 SSO (OIDC), scoped roles, short-lived tokens, MFA inherited; server authz; DB tenant isolation; scoped object storage; redacted logging; cross-tenant tests through ids, filters, joins, jobs, exports, caches, realtime rooms; no global code lists.
- NFR02 encryption, secret rotation, connector egress limits, payload/request limits, attachment scanning, output escaping, CSV sanitization; declarative rules only.
- NFR03 audit of user/service actions, config changes, overrides, approvals, exports, permission-sensitive reads; no credentials in logs; retention/legal hold configurable; clock skew monitored.
- §17.1 targets: event first page p95 < 2 s; 30-day unit dashboard p95 < 3 s; recompute p95 < 60 s; intake 1000 obs/s sustained, 10 000/s burst 15 min; zero accepted-record loss on worker crash; 99.9 % API availability.
- T14 tenant attack on routes, joins, replay, export, socket, cache; T40 soak with worker restart.

## Current implementation (verified)
- Local JWT (24 h access, same secret for refresh), `register` public; guards per controller (fixed in 0.4); no RLS; realtime global (fixed 3.1/1.9); `pi-proxy` open (fixed 1.6); stack traces in errors (fixed 0.4); no rate limiting; no load tests; no indexes on production tables (added progressively from 1.1); no Redis use (container exists, stopped); nginx compression configured by Docker work (verify).

## Target design
**Identity**: `AuthProvider` abstraction (0.4 context) gains `OidcProvider` (openid-client): authorization code + PKCE in the SPA, backend validates ID/access tokens via JWKS, maps claims → user + `user_scopes` (groups → roles per tenant/site); access token lifetime ≤ 15 min, refresh via provider; local JWT provider kept for dev/demo only (`AUTH_PROVIDER=local|oidc`). MFA per provider policy.
**Database isolation**: Postgres **row-level security** on every tenant-scoped table (`USING tenant_id = current_setting('app.tenant_id')::uuid`), set per transaction from `RequestContext`; app role without `BYPASSRLS`; migration-time role has bypass. Composite FKs `(tenant_id, id)` where children reference parents (DB01) added in each sub-phase's migration; a schema test asserts every tenant table has RLS + policy.
**Object storage**: exports/attachments under tenant-prefixed paths; download through authorized streaming endpoint only.
**Secrets & egress**: secrets table encrypted (AES-GCM) with key from env/KMS; rotation command re-encrypts; connector HTTP clients use an allowlist of hosts per connection; TLS verification default; request body limits (1 MiB JSON, 25 MiB uploads), attachment scanning hook (ClamAV container optional), CSV sanitization (2.9), output escaping in exports.
**Audit**: `audit_log` already append-only (2.8); add permission-sensitive read auditing (raw payload views, exports, evidence downloads) and config changes; log redaction filter (tokens, passwords, connection strings); legal hold flag on retention jobs.
**Performance** (ENGINEERING_STANDARDS applied and verified):
- Indexes reviewed with `EXPLAIN ANALYZE` on the top 20 queries (events list, downtime report, period grid, run inputs); add missing composite/partial/GiST indexes.
- N+1 audit: TypeORM query logging in integration tests fails on > N queries per request for list endpoints.
- Redis cache-aside (reuse `instrumental-redis` or Compose `redis`) for hot, rarely-changing reads: code libraries, profiles/rates resolution, calendars/shift instances, feature flags; TTL 5 min; invalidation on write via outbox event → cache bust; never cache period results (bound to runs) or anything tenant-unscoped (keys include tenant).
- Connection pool sized (pg `max` per process), statement timeout 30 s, `maxQueryExecutionTime` slow-query logging (> 500 ms) to logs/metrics.
- `compression` middleware on API for direct clients; nginx brotli/gzip for the SPA; HTTP/2 at the TLS terminator.
- Timeouts + retries with jitter on all outbound calls (PI, webhooks, brokers) — verified by contract tests.
- Stateless API (no in-memory session/lock state; leases in DB) → horizontal scale test with 2 API + 2 worker replicas.
- Frontend: bundle budget, lazy routes, virtualization (3.1) measured with Lighthouse CI (performance ≥ 85 on key pages, LCP < 2.5 s on LAN profile).
**Load/soak** (k6 or Artillery): scripts for §17.1 profile — intake simulators (PI sim + MQTT publisher + Kafka producer) at 1000 obs/s, burst 10 000/s for 15 min, 100 concurrent UI users on events/dashboard/periods; kill a worker mid-run; assert p95s, zero accepted-record loss (counts reconcile), no cross-tenant rows in any response (automated scan of responses for foreign tenant ids).

## Tests
- **T14 full matrix** (integration + e2e): tenant-B identity attempts tenant-A data through: path ids, list filters, joins (period → events of A), replay job on A's connection, export of A's report, socket room join for A's unit, cached endpoint previously warmed by A → all 404/403, no leakage in bodies/counts; `audit_log` records attempts; RLS blocks even a buggy query (test executes a deliberately unscoped repository call under tenant B → 0 rows).
- **T40 soak**: §17.1 load with worker kill → p95 targets met; `accepted == processed + quarantined`; no duplicates; no cross-tenant rows.
- Auth: expired token → 401; token from another issuer → 401; role downgrade → 403 on next request; refresh rotation.
- Secrets: API/logs never contain secrets (regex scan of responses and log output in tests); rotation re-encrypts and old key removed.
- Perf: N+1 guard fails when a relation is loaded lazily in a list; slow query log entry produced for a forced slow query; cache invalidated within one event after code change; Lighthouse budgets pass.
