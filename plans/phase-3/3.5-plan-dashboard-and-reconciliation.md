# 3.5 Plan Dashboard — period grid, reconciliation editor, approval

**Status:** 🧪 implemented 2026-10-10 (UX05 engineer + manager journeys, T36 and T33 in the UI green; behind `v2.planDashboard`, on for Demo Plant) · **Epic:** P3 E10/E09 UI · **Spec:** §16.2 rows PlanDashboard.tsx, Reconcile modal, PlanWaterfallChart.tsx; ACC07–ACC10 (UI), WF01–WF04 (UI), UX05 engineer and manager journeys, UX03, KPI03 (no render-time writes), B9 B10 · **Tests:** UX05 journey e2e; T33 (UI atomic save); T15/T16/T17 displayed correctly · **Depends on:** 3.1, 2.4–2.8

## Goal
Turn the Plan Dashboard into the period accounting workspace: a grid of production periods with target, actual, signed gap, accepted loss, residual, quality and workflow state; a reconciliation editor that shows auto candidates with provenance, links evidence events, validates line by line, saves atomically and handles conflicts; submit/reject/approve/revise with role gating; and a waterfall that closes exactly to actual on either ledger — with no writes on render and no fabricated inputs.

## Spec requirements covered
- §16.2 PlanDashboard: period grid (target, actual, signed gap, accepted loss, residual, quality, state), **no render-time writes**; Reconcile modal: auto/manual provenance, event links, line validation, conflict handling, atomic save, submit/reject/approve; Waterfall: plan/capacity toggle, residual, overproduction/gains, units, drill-through, closes to actual.
- ACC07 editor contents; ACC08 override semantics with preview on delete; ACC09 tolerance adjustment visible; ACC10 submission gate messages.
- WF01–WF04 lifecycle in UI; Open/Reconciled labels as readiness only; "Unlock" = revise.
- UX05: engineer opens period → compares plan and capacity → inspects actuals provenance → accepts/revises candidates → resolves residual/exceptions → submits; manager inspects submitted snapshot and changed inputs → approves/rejects → immutable export.
- UX01: accounting can start as a Plan Dashboard tab with deep links.

## Current implementation (verified)
- `PlanDashboard.tsx` (~3,400 lines): `initializeSampleData` and OEE write on every open; loss rows with free-text period; "Calculate from Plan"/"Calculate from Events" (fake data, B9); fabricated unaccounted %; reconcile modal saving to `reconcile_forms`/`loss_categories` non-transactionally and dropping the event link (B10); financial tiles with flat `lossValuePerUnit`; priority-action buttons without handlers; unmapped-events modal; `PlanWaterfallChart.tsx` from event quantities only, "MT" hard-coded.

## Target design
`features/accounting/` (new tab "Periods" on Plan Dashboard + deep link `/plans/:planId/periods/:periodId`):
- `PeriodGrid`: `GET /production-periods?unitIds&from&to` virtualized rows per shift/day: target, actual (with coverage badge), signed gap, attributed, residual (red if ≠ 0 beyond tolerance, labelled unaccounted/over-accounted), quality state, readiness, workflow state (Draft/InReview/Approved/Stale), last run time; filters by state; realtime invalidation.
- `PeriodDetail`: header (`ScopeHeader` + plan version, calendar version, policy versions, run id, approved/provisional toggle `view=approved|draft`), **ledger toggle** plan/capacity with both totals visible side by side when compared, actuals provenance panel (method, source segments, coverage, exceptions, adjustments), `LossLineEditor`, `ChangeProposalsPanel` (WF04 before/after → accept creates revision), revision history with snapshots.
- `LossLineEditor` (replaces reconcile modal): table of lines grouped by segment — auto candidates (accept / adjust quantity / replace codes / reject with reason), manual lines (reason, impact, OEE component, quantity with `DecimalInput`, evidence event picker filtered to overlapping events, or explicit "no event" / "missing code" flags), overrides show `baseline_changed` alert; footer: target, actual, gap, attributed, residual, over-accounted, tolerance; line-level errors from 422 (`line`, `expectedRemainingAllocation`) rendered inline; **Save** = `PUT …/draft-lines` with `baseRunId` + `expectedVersion`; 409 `RUN_CHANGED` → dialog showing candidate diff → rebase; 412 → latest revision diff → rebase; nothing applied partially (T33).
- Workflow bar: Recompute (202 + progress), Submit (shows gate failures from 422 list), Reject (reason), Approve (hash check; disabled for submitter with explanation; 409 stale → "inputs changed, recompute and resubmit"), Revise ("Unlock"), Cancel draft; immutable approved view with Export (2.9 job → download).
- `Waterfall` (rebind `PlanWaterfallChart.tsx`): server `GET /reports/waterfall?periodIds&ledger=plan|capacity` → bars planned/capacity → exclusion → A → P → Q → good, plus residual, gain, tolerance adjustment, overproduction so the chart **closes to actual**; uom from API; click bar → lines filtered.
- Financial tiles from valuation totals per basis/currency with labels (2.6); remove `lossValuePerUnit`, bottleneck-risk heuristic, "Equipment Status: Active", unhandled buttons.
- Unmapped events modal → moves to integration console quarantine (3.7); link kept.
- Removed on flag flip: `initializeSampleData`, OEE write-back, `addSampleLoss`, `calculateLossesFromProductionData`, fabricated %, `reconcile_forms` writes.

## Decisions / risks
- Keeping it as a tab (UX01 guidance) vs separate workspace: start as tab; promote if cross-plan work demands.
- **Implemented 2026-10-10 — deviations and open points (engineering defaults, not yet reviewed by the owner):**
  - *Backend changes (flagged, additive):* `GET /api/v2/period-summaries` (grid rows: the shown revision's plan-ledger figures after its saved decisions — the plan 2.8 `reconcile` arithmetic, slices summed per period only when they share one unit, else null with `uom_mixed` — plus `residualState`, workflow state incl. `stale`, run, lowest coverage, quality states, products; keyset on `utcStart`; filters `unitIds` (422 `INVALID_REFERENCE`), window, `workflowState`, `view=current|approved`; one bulk load per page, no N+1) and `GET /api/v2/reports/waterfall?periodIds&ledger&view` (1–31 periods; plan: target → kinds after decisions → tolerance adjustment → unaccounted / over-accounted / overproduction + conflict offset → actual; capacity: capacity → exclusion → A → P → Q → gain → residual → good; `closes` checked exactly in decimals; foreign periods 422, mixed units 422 `UOM_MIXED`). Domain `src/domain/reconciliation/waterfall.ts` (+ unit spec: T15, T16, T17, capacity identity). v1 `reconcile-forms` / `loss-categories` / `oee-summaries` writes → 410 `V1_WRITE_GONE` **only for tenants whose `v2.planDashboard` flag is on** (C4: tenants on the v1 dashboard keep the deprecated writes). OpenAPI: 2 operations added, none changed; `schema.d.ts` regenerated; `plan-dashboard-reads.int-spec.ts` (7). No migration (the reads use the existing revision / run / line-set indexes).
  - *Location:* a v2 page at `/plans/:planId` that is the Plan Dashboard while the flag is on (tabs Periods / Plan) instead of a tab inside the 3,400-line v1 component; Production Plans' "View dashboard" goes there. Plans without a v2 version (v1-only, no scenario) say so.
  - *Roles in the UI:* the API exposes no capability list, so every lifecycle action is offered to members and the server decides; the client-side gates are approve / reject for the submitter (the revision's `submittedBy` is the signed-in user → disabled with the `SEPARATION_OF_DUTIES` reason) and for a stale submission. User and service ids are shown shortened ("you" for the signed-in user) — the API returns ids only.
  - *Realtime vs RUN_CHANGED:* a new run arriving by realtime while the user edits rebases the draft at once (dropped decisions listed); the 409 dialog appears when the save reaches the server first (the e2e blocks the socket to make that path deterministic).
  - *Not done here:* waterfall bar click → filtered lines; an approval-snapshot content viewer (history shows the actions); T16 / T17 / T32 e2e (unit tests and the 2.8 backend tests cover them); the financial tiles use the loss-value report of the period window in its default view (contribution margin) only; the v1 unmapped-events modal (3.7) and the v1 dashboard code stay untouched for flag-off tenants; the grid's quality column lists the server's actuals quality states as words.
  - *Fixes outside the feature (flagged):* `PlantSelector` chose and saved a default plant before the saved selection had loaded, so every page load wrote `app-settings/plantSelection` (found by the no-write-on-open assertion) — it now waits for the saved selection. Period commands return the server's view at once and refresh related caches in the background (previously the UI waited for every related refetch). `useCreateExport` (3.3) types the 202 body as an export view although the API answers `{ jobId, statusUrl }` — unchanged here; the new export panel uses `jobId`.
  - *Test data / users:* every e2e run adds to Demo Plant a unit `E2E PD …` (published UTC calendar A 06–14 / B 14–22 / C 22–06), product `E2E PD product …`, approved profile (planning 90 t/h, sustained 100 t/h), reason code `E2E-PD-…`, approved plan `E2E PD plan …` (3000 t over one operational day three days back) with its periods, output and stop events, saved / submitted / approved revisions and one export job. Users: demo `engineer@acme.com` (submits) and `manager@acme.com` (approves; submits for T36), plus `e2e-pd-approver@acme.com` (TenantAdmin of Demo Plant, password in the spec) registered once by the manager through `POST /api/auth/register` as the second approver.
