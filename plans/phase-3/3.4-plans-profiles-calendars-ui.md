# 3.4 Plans, profiles and calendars UI

**Status:** 🧪 2026-10-09 (screens at `/planning` behind `v2.plansProfilesCalendars` in `src/features/plans-profiles-calendars/` — profiles / rates / valuation rates / imports, calendars with server preview and DST warnings, crews, versioned plans with PLAN03 preview, generation and server-gated approval; legacy unit / product fields folded under "Legacy" and the 100 / h template default removed; PLAN03 + CAL Playwright green; two additive read endpoints (flagged) — see Decisions / risks) · **Epic:** P3 E10 · **Spec:** §16.2 rows "Units and products", "Plan form and template wizard"; PLAN01–PLAN06, CAL01–CAL02 (UI), UX03 · **Tests:** PLAN03 preview e2e; CAL preview DST warning e2e · **Depends on:** 3.1, 2.1–2.3

## Goal
Expose capability and schedule as first-class, versioned master data in the retained Units/Products/Plans screens: production profiles with effective-dated rates and margins, calendar versions with shift templates and DST-aware previews, and plan versions with product slices and an exact day/shift period preview before approval — removing the 100 units/hour assumption.

## Spec requirements covered
- §16.2: units/products → profiles, effective capacity/planning rates, units, measurement policy, margin versions; plan form/template wizard → day/shift preview, campaign/concurrent model, schedule exclusions, exact target distribution.
- PLAN02/03 preview, slices, basis, scenario, approval; PLAN06 budget/forecast/MPC history visible.
- CAL01/02 editor + preview with DST warnings; crews independent.
- UX03 states/header.

## Current implementation (verified)
- `plant-hierarchy/UnitList.tsx` captures `idealCycleTime/capacity` (unused); product form has `standardCost`; `PlanForm.tsx` single target + weekly `usefulProductionTime` grid + client-side approval; `TemplateWizard.tsx` 7 steps with 100/h default; `PlanApprovalWorkflow.tsx` role check in UI only; no calendar UI; tenant timezone field unused.

## Target design
`features/master-data/profiles/`: `ProfileList` (unit × product × mode, state, effective), `ProfileEditor` (uom, timebase, capacity model, policies), `RateTable` (kinds nameplate/demonstrated/sustained/planning/budget/forecast as rows × effective intervals; add version → approve; overlap errors from API shown inline), `ValuationRateTable` (basis, currency, effective; "unconfirmed legacy cost" badge until D08), `RateImportDialog` (budget/forecast CSV → job).
`features/master-data/calendars/`: `CalendarVersionList`, `CalendarEditor` (timezone picker IANA, operational day start, shift templates with cross-midnight support, holidays, exclusions), `CalendarPreview` (`POST /calendars/preview` → table of instances with local/UTC/offset, excluded flags, **DST warnings** highlighted), `CrewRotationEditor`.
`features/plans/`: `PlanForm` keeps fields; adds scenario, basis, product slices (sequential campaigns; concurrent behind flag), distribution method, `PeriodPreview` grid (`generate-periods preview=true`): per leaf local date/shift/UTC/target/capacity/excluded with Σ check indicator and warnings (missing rate, no eligible time); `ApprovePlanVersion` button (role-gated by server; shows 409 overlap details); version history with supersession; `TemplateWizard` production-time step replaced by calendar selection, default target from preview (no 100/h).
Units/Products screens: link to profiles; `idealCycleTime/capacity/standardCost` fields hidden behind "legacy" with migration note.

## Decisions / risks
- D03/D08 confirmations surface as banners in these screens until recorded.
- **Implemented 2026-10-09 — deviations and open points (engineering defaults, not yet reviewed by the owner):**
  - *Backend change (flagged, additive):* `GET /api/v2/products` (tenant products for the pickers — tenant master data, the same list for every member; view `{id, code, name, uom, isActive}`, no legacy cost; keyset on `createdAt`) because v2 had no product list; `GET /api/v2/production-plans/{id}/versions` (history newest first, no slices, keyset on `createdAt`; foreign / out-of-scope plans 404) because the version history needed one request instead of one per version. OpenAPI snapshot: 2 operations added, none changed; `schema.d.ts` regenerated; `plans-ui-reads.int-spec.ts` (3). No migration (filters ride on `UQ_products_tenant_code` and `plan_versions (plan_id, version)`).
  - *Client layer:* `V2ApiError.details` (the API03 envelope's `details`, e.g. `conflicts`); `RepairUntyped` in `schema-types.ts` now repairs nested DTO arrays too (slices, templates had `Record<string, never>` fields); resources `products`, `calendars`, `crews` with 5 min stale time; change types `calendar_version`, `crew` invalidate calendars / shift instances / periods / plans.
  - *Screen location:* one new route `/planning` with three tabs (Plans, Profiles & rates, Calendars & crews) instead of rebinding the retained screens — the v1 Production Plans page (with the 3.5 Plan Dashboard) and Master Data stay as they are (C4) and link to it; one flag `v2.plansProfilesCalendars` instead of `v2.plans` / `v2.masterData`.
  - *Roles:* the API exposes no capability list, so every control is offered to members and the server decides; refusals are shown with their code — role (`FORBIDDEN_ROLE`, `READ_ONLY_ROLE`), scope (`TENANT_SCOPE_REQUIRED`, `SITE_SCOPE_REQUIRED`), separation of duties, state (`VERSION_NOT_DRAFT`, `PERIODS_NOT_GENERATED`, `DRAFT_EXISTS`), overlap with the conflicting versions, stale (412, reload offered). Plan previews need a plan writer (the API's rule).
  - *Times:* profile / rate / plan instants are typed on the plant clock (default site zone, else tenant, else labelled UTC — Demo Plant's site has the UTC fallback) and sent as UTC; calendar exclusions on the calendar's own zone; calendar dates are operational dates.
  - *Calendar editor defaults:* a new version starts from the D03 shape (plant zone, 06:00, A/B/C 3 × 8 h) with an empty effective date — the user still saves and publishes; nothing is seeded. "Reduced" holidays are shown as the API stores them with "no reduction rule decided yet".
  - *Preview figures:* the scheduled total, per-instance durations, offsets, warnings, period targets, capacities, totals and job results are the server's; the browser only labels offsets and compares the server total with the header target as decimal strings for the Σ badge (no arithmetic). Per-day totals are not shown (the preview API returns the range total; preview one day to see a 23 / 25 h day).
  - *Template wizard:* the calendar step replaces the weekly production-time grid only while the flag is on; templates keep their stored `usefulProductionTime` (no backend template change). The "hours × 100 units / h" default quantity is removed from the v1 plan form and "create from template" in both flag states (fabricated rate, CLAUDE.md) — v1 behaviour change: the quantity starts at 0 instead of a guess.
  - *Not done here:* FX rates, valuation policies and impact-code cost-per-hour rates (3.8 / finance screens), a unit / product rebind of Master Data (only legacy fields and links), manual per-shift targets entry (the `manual` basis is selectable but per-leaf targets are not editable in the form), a template-wizard e2e (covered by the static check), axe checks (not in A3).
  - *Test data:* every e2e run adds to Demo Plant two units `E2E PLAN …` / `E2E CAL …` with unit calendars (UTC 6 / 6 / 8 h with a no-demand exclusion version; Europe/Berlin), one product `E2E PLAN product …`, an approved profile with planning / sustained rates (a superseding sustained v2), and an approved plan `E2E PLAN …` with its periods.
