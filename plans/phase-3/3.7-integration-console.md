# 3.7 Integration console — connections, jobs, mappings, quarantine, replay

**Status:** 🧪 implemented 2026-10-10 (UX06 Playwright journey green; MQTT / Kafka panels wait for 1.8 / 1.9) · **Epic:** P3 E10 · **Spec:** §16.2 rows "PIIntegration.tsx and sync manager", "New MQTT and Kafka panels"; UX06 integration journey; ING02 real stop/pause; ING05 quarantine resolution; PI02 preview before activation; I12 I15 · **Tests:** UX06 journey e2e · **Depends on:** 3.1, 1.5–1.9

## Goal
Extend the existing Connectivity/PI Integration page into a source-neutral console: configure PI, MQTT and Kafka connections with staged diagnostics, discover sources, map with the shared field catalog and preview, run multiple durable jobs with real start/pause/resume/stop, watch health, resolve quarantine, and run bounded replays — showing each stage's result so "connected" is never mistaken for "accounting works".

## Spec requirements covered
- §16.2: preserve PI browsing; add shared field catalog, preview, multiple jobs, real stop/pause, health and replay; MQTT/Kafka panels with broker/security references, topics, schemas, event-time preview, identity strategy, durable intake test.
- UX06: configure → validate permissions/capabilities → discover → map sample → preview quantities/units/times → start limited ingestion → resolve quarantine → bounded backfill → activate production job with health alarms; display each stage and result.
- ING02 job commands audited; ING05 quarantine with preview/validate/mapping revision/replay; PI02 no credentials in browser; §4.2 secrets by reference.

- `pages/integrations/PIIntegration.tsx` (AF browsing, template discovery, attribute mapping with its own defaults, bind tenant root), `components/pi/PIEventSyncManager.tsx` (interval/lookback, `stopSync` no-op, one job, drops template/maxCount), `HierarchyMappingManager.tsx` (manual identifier entry, no AF picker), `Connectivity.tsx` tabs with simulated protocol cards, `connectivityWebSocket.ts` unused; PI credentials handled client-side for `pi-proxy`.

## Target design
`features/integrations/`:
- `ConnectionsList` (`GET /connections`, source type, state, health, jobs count) → `ConnectionWizard` per source type with capability-driven forms (PI: base URL, auth mode, secret ref, AF server/db; MQTT: broker, protocol version, TLS refs, topics, QoS, session, payload mapping, identity strategy; Kafka: brokers, group, security, topics, decoder, registry, offset policy); secrets entered once, stored by reference, never echoed.
- `DiagnosticsPanel`: `POST /connections/{id}/test` → stage results DNS / TLS / auth / authz / version / read (PI) or connect / subscribe / sample (MQTT) / metadata / consume-sample (Kafka), each pass/fail with detail.
- `DiscoveryBrowser`: AF tree/templates/attributes (reuse existing PI browser components), MQTT topic sampler, Kafka topic/partition viewer; "bind" creates `source_mappings` with the picked identifier (fixes manual typing) and shows precedence/ambiguity.
- `MappingEditor`: attribute → field from `GET /field-catalog` (shared, typed), per-template version, field-by-field override indicator; `Preview` runs sample frames/messages through the server mapping → resulting event/sample with units, times (plant tz), quality, exceptions.
- `JobsPanel`: multiple `ingestion_jobs` per connection (scope, templates/topics, cadence, recovery windows); commands start/pause/resume/stop with confirmation and audit trail; live state (lease owner, heartbeat, committed cursor age, last observation, retry count, errors); health badges from job health; `Backfill/Replay` wizard (from/to, scopes, dry-run counts → run → progress via `GET /jobs/{id}`).
- `QuarantineInbox`: `GET /ingestion-exceptions` grouped by error code/connection with first/last seen and occurrences; detail shows raw payload (authorized), suggestions (e.g. closest codes), actions: create/adjust mapping, assign owner, mark irrecoverable with reason, **replay** (dry-run first); unmapped PI events live here (replaces Plan Dashboard modal).
- `StageTracker`: UX06 stage checklist per connection with the result of each stage and timestamps.
- Removed: client-side PI credential use, `stopSync` no-op, single-job assumption, simulated protocol cards (R1 shows only PI/MQTT/Kafka; others "planned R2").

## Decisions / risks
- Raw payload display must be authorized (integration administrator role) and redacted of secrets; large payloads via reference download. **Done:** `GET /v2/ingestion-exceptions/{id}` returns the payload to integration_admin / manager_approver / SuperAdmin only, credential-like keys redacted (`payloadVisible` flag); `payloadRef` is shown as is (no download endpoint yet).
- **Implemented 2026-10-10 — deviations and open points (engineering defaults, not yet reviewed by the owner):**
  - *Backend changes (additive, flagged in the OpenAPI snapshot: 3 operations added, none changed; no migration):* `PATCH /v2/connections/{id}` (If-Match; 409 `LEGACY_CONNECTION` for v1 PI mirrors, 422 `SECRET_IN_CONFIG` / `INVALID_ENDPOINT_CONFIG`, `configVersion` + 1 on endpoint or secret change), `GET /v2/connections/{id}/sample` (writers only; optional adapter method `sample`, PI implementation `src/integration/pi/pi-sample.ts`; 422 `SAMPLE_UNSUPPORTED` / `INVALID_RANGE`), `POST /v2/attribute-mappings/preview` (`@ReadOnlyAllowed`, `AttributeMappingPreviewService`). Behaviour changes on existing routes: the exception detail now adds `raw.payloadVisible` and withholds / redacts the payload by role; `discover` (and `sample`) answer a classified source failure as 502 with the adapter code instead of a 500. `test/integration/integration-console.int-spec.ts` (9 tests, PI simulator).
  - *Not built / API gaps:* Kafka panel (adapter 1.9 not built — D10; shown as not available; the MQTT panel landed with plan 1.8 WP3 step 5 on 11 Oct 2026 under `src/features/integration-console/mqtt/`); AF element-tree / template browsing (the adapter's `discover` lists servers and databases only, the simulator has no element or template listing — discovery is by sampling recent frames, which yields the templates and elements that actually produce data); quarantine grouping counts per code / connection (server filters instead; a grouped count needs an aggregate endpoint); assigning an owner to an exception (no API); a persisted connection-test history (the stage tracker keeps the last test per browser session); signal creation in the UI (signals are defined through `POST /v2/signals`, the console lists, previews and backfills them); `payloadRef` download.
  - *IndexedDB ratchet:* the console uses the v2 API only (`integration-console-hygiene.test.ts` bans IndexedDB / StorageService / PIStore / connector stores / browser storage); `code-hygiene.test.ts` gains a rule that new product code never imports an IndexedDB user. The v1 users (`PIStore`, `UniversalConnectorDB`, historian, protocol / streaming demo services) stay for the v1 Connectivity / historian screens of flag-off plants (C4). Removing the unused `src/services/streaming/` (three `Math.random` files and the `FilterEngine` IndexedDB user, imported by nothing) was blocked by the session's permission policy for deletions — left for the owner.
  - *Secrets in the browser:* the password lives only in the form state and the in-memory mutation until the dialog closes; it is never put in any storage (Vitest and Playwright assert local / session storage and every API response body).
