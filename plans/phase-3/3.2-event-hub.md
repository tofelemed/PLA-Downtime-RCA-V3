# 3.2 Event Hub on v2

**Status:** ⬜ not started · **Epic:** P3 E10 · **Spec:** §16.2 EventHub row, UX04 operator journey, UX03, DT08–DT11 (UI), ING06 source/effective display, B8 B15 B16 · **Tests:** UX04 journey e2e; T22 consumer (rules from server) · **Depends on:** 3.1, 1.1–1.4

## Goal
Keep the Event Hub shell and its journeys, but bind it to v2: server-side combined filters and pagination, a current-stops panel, explicit duration, source vs effective values, split/merge/bulk-code/close dialogs, evidence drawer, scoped realtime, and remove every fabricated or browser-only behaviour.

## Spec requirements covered
- §16.2: combined filters, current stops, explicit duration, source/effective comparison, split/merge, bulk code, close, evidence drawer; dependency on events, revisions, operations, scoped realtime.
- UX04: choose unit and shift → inspect current stops and source quality → code reason → split if causes changed → review impacted periods → save → confirmed update; reconnect preserves unsaved form and requires conflict review if server revision changed.
- UX03 states and status header; no fabricated data (random IOW trend, `Simulate Events`, `Math.random` crew).
- DT10 bulk preview; DT11 three states displayed (physical/coding/RCA) with legacy label adapter for familiarity.

## Current implementation (verified)
- `pages/EventHub.tsx` (~2,500 lines): tabs per event type, client-side filters over full tenant list, quick stats mixing duration units, create dialog without duration input (B8), edit via `EventFormFields.tsx`, status automation rules from `localStorage` (B15), random IOW trend fallback (B16), `planId` only for output events, tenant from `session` vs `plantSelection` inconsistency, tab visibility in IndexedDB, CSV export in browser (unsanitized), `Simulate Events` and `Pull from PI` buttons.

## Target design
**Structure** (split the monolith; ENGINEERING_STANDARDS component size): `features/events/` — `EventHubPage` (layout, flag switch), `EventFilters` (server filter model: units, assets, physicalTypes, scheduleClasses, codingStates, rcaStates, reasons, from/to, isOpen, text), `EventList` (virtualized infinite list via `useProductionEvents`), `CurrentStopsPanel` (`isOpen=true`, elapsed from server `asOf`), `EventDetailDrawer` (effective vs source columns, revisions timeline, coding history, review items with keep/accept), `EventForm` (create/edit: start, end **or** duration (minutes input → seconds), unit/asset, physical type, schedule class, codes via tree picker, description; DTO = §15.3), `SplitDialog` (timestamp slider within interval, preview of children), `MergeDialog` (candidate adjacent events, gap policy), `BulkCodeDialog` (selection → preview table before/after/exclusions/impacted periods → apply; >500 → job progress), `CloseStopDialog`, `EvidenceDrawer` (raw observations/attributes/attachments from `GET …/evidence`), `ImpactedPeriodsPreview` (periods overlapping the event with readiness state — UX04 "review impacted periods").
**Data**: all lists via cursor pagination; quick stats from `GET /reports/downtime?groupBy=none` for the current filter (server union seconds), not from loaded rows; realtime invalidation by scope.
**Status display**: three state chips + legacy label tooltip; status rules evaluated server-side (3.8 rule engine) — the UI shows the rule-derived coding state, no local rules.
**Duration**: one `DurationText`; CSV export → `POST /exports {report: events, filters}` job (2.9) with sanitization.
**Removed**: `Simulate Events` (demo env only), random IOW fallback (show `DataState source-offline` with the PI error), `Math.random` crew suggestion, `localStorage` rules, IndexedDB tab visibility (→ `app-settings`), `Pull from PI` (moves to integration console 3.7 as a job action).
**Conflict handling**: form keeps a draft in memory + `sessionStorage` keyed by event id/revision; on save with 412 → side-by-side diff dialog (server vs mine) → retry with new `If-Match`.
**Accessibility**: keyboard navigation in list/dialogs, text labels beside state colours, tablet layout (UX07).

Reconnect mid-edit: form draft restored; server revision changed → conflict dialog shown; resolve → saved.
- Filters: every filter round-trips to server params; combined filters return intersection (network assertions); pagination stable while new events arrive.
- Create with end+duration mismatch → field error from 422; create open stop → appears in current stops; close → disappears with duration.
- Bulk-code preview excludes stale/foreign; apply 10 events atomic; 600 events → job progress → partial state surfaced.
- No `Math.random`, no `localStorage` rules, no IndexedDB in the Event Hub bundle (static check).
- Accessibility: axe checks pass on page and dialogs; keyboard-only flow completes.
