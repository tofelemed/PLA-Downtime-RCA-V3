# 3.1 Frontend foundation — typed v2 client, query cache, scoped realtime, UX states

**Status:** 🧪 implemented 2026-10-09 (foundation in place: generated v2 types + client, query layer, scoped realtime on both sides, UX kit, server feature flags, route splitting and bundle budget; Event Hub uses the scoped channel behind `v2.eventHub`; screen rebinding is 3.2–3.9 — see Decisions / risks) · **Epic:** P3 E10 · **Spec:** UX01–UX03, API05 (client side), G08, I14 timezone display · **Tests:** T23 (client dedupe/resync), T24 (shared result version across chart/totals/export) · **Depends on:** 0.4, 1.9, 2.9

## Goal
Replace the hand-written `httpClient` + `useEffect` data layer with a generated, typed v2 client and TanStack Query, add an authenticated scoped realtime client with sequence resync, standard UX state components, plant-timezone/unit/decimal formatting, route-level code splitting and feature flags — so every screen migration in 3.2–3.9 is a rebind, not a rewrite.

## Spec requirements covered
- UX01 retain navigation/components; add Downtime Analysis and integration console entry points.
- UX02 one typed client + shared cache; query keys include tenant, scope, window, timezone, filters, ledger, revision selector; all filtering/pagination on the server; mutations invalidate; clear cache on tenant change/session expiry; **never load a whole tenant's events to compute KPIs**.
- UX03 standard status display (scope, tz, uom, baseline, approved/provisional, as-of, freshness) and the seven UX states; remove fabricated data.
- API05 client: subscribe to authorized rooms; refetch snapshot after gap/reconnect; dedupe by `domainEventId`.
- §3.3 render plant-local time with zone and offset; decimals as strings → formatted with explicit units.

## Current implementation (verified)
- `src/services/api/httpClient.ts` (Bearer from `localStorage`), ~20 `*Api.ts` hand-written clients; `MasterDataService` facade; `QueryClientProvider` mounted but **`useQuery` never used**; every screen `useEffect`+`useState`, duplicate fetches (PLA Pareto/Trend/Waterfall/table each fetch all events); `productionEventsWebSocket.ts` only in Event Hub, full refetch per message; realtime unauthenticated/global; `StorageService` IndexedDB still used by `TabVisibilityService`, streaming services, seeders; durations shown in mixed units; browser-local time display; `src/services/api/apiBaseUrl.ts` added by Docker work.
- Bundle: single entry, `react-flow-renderer` **and** `reactflow` both installed, `react-chrono`, recharts — no code splitting, no bundle analysis.

## Target design
**Typed client**: `openapi-typescript` generates `src/api/v2/schema.d.ts` from the committed OpenAPI v2 snapshot (0.4); thin `v2Client` (fetch wrapper) adds auth header, `X-Correlation-Id`, `X-Tenant-Id` (SuperAdmin selection), `Idempotency-Key` on commands, `If-Match` from cached ETags, parses the API03 error envelope into `ApiError {code, fieldErrors, correlationId, retryable}`; 412 → `StaleRevisionError` carrying latest revision; 429 → retry with `Retry-After` (bounded).
**Query layer**: `src/api/v2/queries/*.ts` — `queryKeys` factory `['v2', tenantId, resource, scope, {from,to,tz}, filters, ledger, revisionSelector]`; hooks per resource (`useProductionEvents`, `useProductionPeriod`, `useDowntimeReport` …) with `useInfiniteQuery` for cursor lists; `staleTime` per resource class (master data 5 min, periods 30 s, reports until invalidated); mutations call `invalidateQueries` on related keys (event → events, periods overlapping, reports); `queryClient.clear()` on tenant change and on 401 refresh failure.
**Realtime**: `src/realtime/scopedSocket.ts` — connects with the access token, joins rooms for current tenant/site/unit scope, receives `{entityId, revision, type, occurredAt, scope, seq}`; dedupes by `domainEventId`; on `seq` gap or reconnect → `invalidateQueries` for the scope (snapshot refetch) instead of applying partial data; permission change → re-join.
**UX kit**: `<ScopeHeader>` (scope, tz with offset, uom, baseline, approved/provisional badge, as-of, freshness), `<DataState>` (loading skeleton / empty / no-permission / source-offline / incomplete / calculation-pending / error with correlation id), `<DurationText seconds>` (one place that formats seconds), `<Quantity value uom>`, `<PlantTime iso tz>` (luxon), `<DecimalInput>` (string-based, 8 dp).
**Feature flags**: `GET /api/v2/feature-flags` (tenant-scoped) → `useFlag('v2.eventHub')`; routes render v1 or v2 component accordingly.
**Performance (ENGINEERING_STANDARDS)**: `React.lazy` per route and for chart/diagram/editor components (recharts, reactflow, react-chrono); remove `react-flow-renderer` duplicate; `rollup-plugin-visualizer` in `build:analyze`; `@tanstack/react-virtual` for long tables; debounced search/filters; nginx gzip/brotli + immutable hashed asset caching (Docker work) verified; prefetch next page on scroll.
**Removal**: `StorageService` out of product paths (`TabVisibilityService` → `app-settings`; streaming demo services behind `DEMO_MODE`); `window.*` debug globals and seeders out of production bundle (`import.meta.env.PROD` guard or separate demo entry).

## Decisions / risks
- `openapi-typescript` + fetch keeps zero runtime deps; `orval`/`openapi-fetch` are alternatives — decide in step 1.
- Feature flags from the server (not build-time) so pilot units can switch screens without redeploying (MIG02/MIG05).
- **Implemented 2026-10-09 — deviations and open points (engineering defaults, not yet reviewed by the owner):**
  - *Response types* are hand-mirrored in `src/api/v2/types/` because the OpenAPI snapshot documents no response bodies; nullable scalars without an explicit `type` come out as `Record<string, never>` and are loosened by `RepairUntyped` in `schema-types.ts`. Fix at the source (backend `@ApiOkResponse` / typed `@ApiProperty`) so the views can be generated too.
  - *Realtime transport:* the API tails the outbox (poll `REALTIME_POLL_MS`, default 1 s) instead of LISTEN/NOTIFY or Kafka; `seq` = outbox id, gap detection by `prevSeq` per room; the replay buffer is per process (`REALTIME_REPLAY_SIZE`, default 500) — after a restart, or on another API instance, a resume answers `resync`. Several API instances will need a shared Socket.IO adapter (3.11 / 3.12).
  - *Scope of messages:* a message without any unit reaches tenant-wide sockets only; unit-limited users see it through query staleness. The legacy `/socket.io` namespace still broadcasts v1 entities to every (unauthenticated) client — pre-existing, kept for the v1 screens (C4); it must be closed in 3.11 when the v1 screens are retired.
  - *Socket test:* the backend integration spec drives the gateway with in-memory sockets (no `socket.io-client` in the backend package; adding it as a devDependency would allow a wire-level test — owner to decide).
  - *IndexedDB still in product paths:* `EnhancedHistorianPage` (historian history), `PIStore`, `UniversalConnectorDB` and the protocol / streaming demo services used by Connectivity, Dashboard, the Event Hub PI view and the plant hierarchy lists — removed with the integration console / historian work (3.7); ratcheted by `code-hygiene.test.ts`. `app_settings` (plant selection, tab visibility) is a global key/value table, not tenant-scoped (3.11).
  - *T24 Playwright:* no report page exists before 3.3 / 3.6; the shared-snapshot rule lives in `reportSnapshot` / `reportKey` and is unit-tested; the network-interception e2e lands with the first report page.
  - *UX01 entry points* (Downtime Analysis, integration console) are added with their screens in 3.3 / 3.7.
  - *Dev-only seeding:* the Data Seeding page is no longer in production builds (A4: legacy seeders retire with 3.1); `HierarchyMappingSeeder` stays (Master Data button, 3.8).
  - `@size-limit/file` was added with `size-limit` (its required file plugin).
