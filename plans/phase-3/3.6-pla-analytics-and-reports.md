# 3.6 PLA Analytics and Reports on server snapshots

**Status:** 🧪 implemented 2026-10-10 (AN02 / AN03 journeys, T24 and T41 (UI) Playwright green; PLA Analytics, Reports and Dashboard behind `v2.plaAnalytics`, on for Demo Plant) · **Epic:** P3 E10/E11 · **Spec:** AN02, AN03, KPI03/KPI04 labels, §16.2 rows PLADashboard.tsx and Reports, UX03, B11, G07 · **Tests:** T24, T41 (UI shows null not 87 %); AN02 view checklist e2e · **Depends on:** 3.1, 2.6, 2.7, 2.9

## Goal
Rebind PLA Analytics, Dashboard and Reports to one authoritative server snapshot per view: real OEE with its policy label, working grouping controls, cumulative Pareto, loss tree, reconciliation status and age, unaccounted/over-accounted trends, margin/cost impact, quality coverage, repeat causes and top opportunities; Reports with named units, full scope, actual period dates, approved-version selector and asynchronous exports.

## Spec requirements covered
- AN02 PLA views: plan and capacity waterfalls, loss tree by reason/impact/OEE, unit and product trends, reconciliation status and age, unaccounted/over-accounted trends, cost or margin impact, quality coverage, repeat causes, top opportunities; waterfall closes exactly.
- AN03 aggregation from numerators/denominators; site-local grouping; cross-site comparison labels; CSV/PDF exports with filters, generated time, status, revision.
- KPI03 no render-time computation/writes; KPI04 never switch tiles between OEE definitions without a label.
- §16.2: PLADashboard real OEE policy label, active grouping control, cumulative Pareto, consistent drill-down, shared snapshot; Reports named units, full scope, actual period dates, approved version selector, async exports.
- UX03 header/states; remove heuristics (B11 unwired selector, heuristic OEE, UUID labels).

## Current implementation (verified)
- `PLADashboard.tsx`: heuristic OEE (`UnifiedAnalyticsService`), filters whose values never match data (category, shift), unwired trend selector (B11), Pareto without cumulative, waterfall from event quantities, refresh = reload, dead controls. `Dashboard.tsx`/`DashboardAnalytics.tsx` duplicate heuristics. `Reports.tsx`: server reports but `unitId` never sent, unit labels as UUID prefixes, `createdAt` filtering (fixed server-side in 2.7), JSON export client-side.

## Target design
`features/analytics/`:
- Shared `AnalyticsScope` (URL state: site/units/products, window in plant tz, ledger, approvedOnly, policy operational|reconciled) feeding every widget; each response's `calculationRunIds/policyVersion/coverage/isProvisional` shown in `ScopeHeader` and stamped on export jobs (T24).
- PLA page tabs: **Waterfall** (`/reports/waterfall`, ledger toggle, closes to actual incl. residual/gain/tolerance/overproduction), **Loss tree** (`/reports/loss-tree?groupBy=reason|impact|oee&metric=qty|margin|standard_cost|operational_cost`, treemap/sunburst lazy-loaded, aggregation scope label), **Trends** (`groupBy=shift|day|week|month` wired; unit and product series; unaccounted and over-accounted series), **Reconciliation** (status counts, age distribution, overdue list → deep link to 3.5), **Quality coverage** (coverage ratio and quality-state distribution), **Repeat causes** (reason recurrence across periods/assets), **Top opportunities** (largest valued losses by reason/asset with basis label), **OEE** (operational vs reconciled side by side, each labelled with policy and denominator; null states rendered as "not available: <reason>", T41).
- `Dashboard.tsx` tiles rebound to `/reports/dashboard` v2 (OEE with label, downtime, open periods, overdue reconciliations, RCA/tasks); `DashboardAnalytics.tsx` and `UnifiedAnalyticsService` deleted.
- Reports page: unit names from API (joined server-side), `unitIds` always sent, date filters apply to **period dates**, revision selector (approved/latest draft/run), tabs for downtime and reconciliation added, exports via `POST /exports` (CSV/PDF) with job progress and download; header shows generated time, status, revision.
- Removed: heuristic OEE, severity $/h fallback, category/shift filter lists that don't match data (now server-provided option lists), `window.location.reload`, dead Fullscreen/viewMode.

## Decisions / risks
- Treemap/sunburst: recharts has Treemap; sunburst needs d3 — ask before adding. **Done:** Recharts `Treemap` only (lazy chunk); no sunburst, no new dependency.
- **Implemented 2026-10-10 — deviations and open points (engineering defaults, not yet reviewed by the owner):**
  - *Backend changes (flagged, additive, no migration):* five side-effect-free reads in `src/v2/pla-reports/` on the 2.7 report scope (`resolveReportScope`: tenant / unit scope from identity, 422 `INVALID_REFERENCE`, window ≤ 400 days by period start, `approvedOnly`), each with the 2.7 `AnalyticsResponse` envelope (run ids, policy versions, coverage, provisional): `GET /v2/reports/scope-waterfall` (the 3.5 waterfall over every period of the window — same bars and exact closure check; 422 `UOM_MIXED`; ≤ 1500 periods, else 422 `TOO_MANY_PERIODS`), `GET /v2/reports/loss-tree` (Σ calculation-run loss lines of the shown run per reason / impact / OEE component / kind / unit, quantity per uom or one valuation view per currency, Pareto shares, `limit` for top N; unvalued or FX-missing → null with reasons, never 0), `GET /v2/reports/reconciliation-trend` (unaccounted / over-accounted / overproduction per site-local shift / day / ISO week / month = the waterfall's residual steps, per uom), `GET /v2/reports/reconciliation-status` (workflow and residual state of each period's current revision, age buckets, overdue list with unit name and plan id; `overdueAfterHours` default 48, `asOf` default now), `GET /v2/reports/actuals-quality` (quality state and coverage band per slice, lowest coverage, measured vs estimated per uom). The period-state reports reuse `loadPeriodStates` (one bulk load, no N+1) with a new internal revision selector `shown` (approved, else the open draft — the 2.7 rule), so their run ids equal the KPI reports' (T24). OpenAPI: 5 operations added, none changed; `schema.d.ts` regenerated; `test/integration/pla-reports.int-spec.ts` (7) and `src/v2/pla-reports/pla-reports.spec.ts` (3).
  - *Loss-tree basis:* calculation-run loss lines, not an open draft's reconciliation decisions (manual lines and rejections are in the waterfall) — stated on the page. Without decisions, and always on the capacity ledger, the loss-tree total equals the waterfall's losses (asserted by the integration spec and the e2e). A decision-aware tree needs the 2.8 line sets per reason (later).
  - *Not built / API gaps:* `/reports/dashboard` (the dashboard composes the existing reports instead); task tiles on the v2 dashboard (RCA tiles built 15 Oct from `GET /v2/rcas/summary`; PDF export built 15 Oct; a PLA site filter selecting a site's units built 15 Oct); a "specific calculation run" revision selector (the API offers approved / approved-else-draft); cross-site comparison labels beyond the plant timezone and the per-view baseline / product labels (the report scope has no `siteIds`; every group is site-local by its stored operational date); drill-down from a loss-tree bar to its events (the tree links to Downtime Analysis with the same scope, whose 3.3 Pareto drill-through applies); virtualised lists (every list here is bounded: ≤ 50 overdue rows, top-N groups).
  - *Heuristic removal:* the flag-on path never mounts `PLADashboard.tsx`, `Dashboard.tsx`, `DashboardAnalytics.tsx` or the v1 `Reports.tsx` (heuristic OEE, severity $/h fallback, category / shift filters that never match, `window.location.reload`, dead controls); the v1 files stay for flag-off plants (C4) instead of being deleted as the plan proposed.
  - *Test touched outside the feature:* `e2e/reports.spec.ts` (v1) asserted the v1 tabs on Demo Plant, which now shows v2 — it checks whichever binding is active.
