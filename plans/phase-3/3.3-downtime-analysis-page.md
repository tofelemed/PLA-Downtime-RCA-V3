# 3.3 Downtime Analysis page

**Status:** ⬜ not started · **Epic:** P3 E10/E11 · **Spec:** AN01, KPI05–KPI08 display, DT04 unknown coverage, §16.2 "Downtime Analysis" row, UX03, AN03 grouping · **Tests:** AN01 fixture-driven e2e; T24 · **Depends on:** 3.1, 2.7, 1.10

## Goal
A new page that answers "what is down, why, how often, where, and is it getting better" from server read models only — currently down, KPI summary, reason-hierarchy Pareto with cumulative share, duration/frequency toggle, trends, asset bad actors, crew and calendar comparisons, and a state timeline — with every bar drilling to the same filtered intervals and calculation version.

## Spec requirements covered
- AN01 required views and drill-through with identical server filters and calculation version.
- KPI05–KPI08 labels: planned/unplanned/micro/unknown, stop count vs carry-in, mean completed-stop cohort, scheduled availability vs onstream factor, MTBF with exposure/count, MTTR vs mean downtime to restore.
- DT04 lower-bound known downtime + unknown duration; provisional vs confirmed.
- AN03 site-local grouping; cross-site comparison shows tz/unit/mode/product/policy/coverage.
- UX03 header and states.

## Current implementation (verified)
- No downtime page. Pieces exist in PLA Analytics (Pareto by impact code without cumulative line; trend with unwired selector), Dashboard "top impacted assets" by count, heuristic OEE. No MTBF/MTTR, no timeline, no planned/unplanned, no shift comparison (filter values mismatch).

## Target design
**Route** `/downtime` (nav entry per UX01). `features/downtime/`:
- `DowntimeFilters`: scope (site/units/assets), window presets in plant tz, schedule class (all/planned/unplanned/external/unknown), reason subtree, product, shift, crew; persisted in URL search params (shareable; export uses the same).
- `CurrentlyDownPanel`: `GET /production-events?isOpen=true&physicalTypes=downtime&unitIds…` + `GET /equipment-state-segments?open=true` → unit/asset, state, since, elapsed (server asOf), source quality, provisional flag; actions: code / close (reuse 3.2 dialogs).
- `KpiSummary`: from `GET /reports/downtime` and `GET /reports/reliability` for the filter — total, planned, unplanned, micro-stop, **unknown** (with "known downtime is a lower bound" note when > 0), stop count + carry-in, mean completed-stop duration (cohort label), scheduled availability, onstream factor (denominator label), MTBF (null → "no failures in window, exposure X h"), MTTR or "mean downtime to restore" per label from the API.
- `ReasonPareto`: `groupBy=reasonLevel1` → click → `reasonLevel2` under that parent → … → event list; `metric=duration|frequency` toggle; cumulative % line; bars labelled with `DurationText`.
- `TrendChart`: `groupBy=shift|day|week|month` (site-local), stacked by schedule class; clipped durations (KPI06 note that cohort differs from mean-stop).
- `BadActors`: `groupBy=asset` sorted by duration with frequency secondary; aggregation scope label ("asset totals not additive to unit downtime", ACC06).
- `CrewComparison` / `CalendarComparison`: `groupBy=crew` and side-by-side windows; both show coverage and policy version.
- `StateTimeline`: Gantt of `equipment_state_segments` per unit/asset (lazy-loaded chart; virtualized rows); unknown segments hatched; derived events overlaid; click → event detail drawer.
- Every widget carries `calculationRunIds`/`asOf`/`isProvisional` from its response; `<ScopeHeader>` shows them; export button creates a job with the same filters (2.9).
**Data**: no client aggregation; charts render server numerators/denominators; drill-down passes the same filter object + `runIds` to the event list route (T24).

- Zero failures → MTBF tile shows null state with exposure; no repair evidence → tile titled "Mean downtime to restore".
- Trend grouping by shift respects plant tz across a DST day (T19 data).
