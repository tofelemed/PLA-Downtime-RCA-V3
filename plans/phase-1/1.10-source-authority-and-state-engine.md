# 1.10 Source authority and the downtime state engine

**Status:** ⬜ not started · **Epic:** P1 E06 (SRC) + E03 (DT) · **Spec:** SRC01–SRC02, DT01–DT04, DT06–DT07, §14.2 `equipment_state_segments`, `event_impacts`, `event_relations(occurrence)`, D13 · **Tests:** T11 T12; DT fixtures (debounce, micro-stop, staleness, overlap allocation) · **Depends on:** 1.1, 1.7, and 1.8 or 1.9

## Goal
Turn signals into equipment states and automatically generated downtime events with debounce, micro-stop and staleness rules; model how an asset outage impacts a unit; correlate explicit source events (PI EFs) with derived stops so nothing is double counted; and enforce one authoritative source per measurement.

## Spec requirements covered
- DT01 state observations + effective non-overlapping segments per unit/asset; states Running, Stopped, ReducedRate, Idle, Changeover, Unknown; source health separate; rules (digital mapping, thresholds, hysteresis, debounce, min stop, max stale) by equipment class, effective-dated, with preview.
- DT02 defaults: 5 s debounce, 60 s micro-stop, 10 s restart confirmation, staleness = max(60 s, 3 × sample interval); effective start = first qualifying observation; ReducedRate thresholds per product/mode; states outside schedule detected but excluded from OEE denominator.
- DT03 close at first qualifying recovery after confirmation; confirmation delay not added; micro-stops → performance; stops ≥ threshold → availability; not both.
- DT04 stale/bad → Unknown at validity boundary; lower-bound known downtime + unknown duration; estimated end requires review; provisional vs confirmed duration.
- DT06 unit impact rules: none / full stop / fixed fraction / measured; shared causes link to impacted units with one cause reference.
- DT07 overlap allocation: explicit primary cause or weights summing to one; precedence manual → source impact → validated rule → unclassified; never by arrival order.
- SRC01 one authority per unit/product/measurement/interval; fallback segments + banner; reconcile overlaps on return.
- SRC02 explicit and state-derived events for the same stop → one canonical **impact occurrence**; primary timing source; ambiguous → review.

## Current implementation (verified)
- Nothing. Downtime exists only as events users or PI created. No state model, no impact model, no authority policy. `OPCUAMonitoringService`/`RealTimeAnalytics` in the browser are display-only.

## Target design
**Schema (migration `0008-state-engine`)**
```
state_rules: id, tenant_id, scope (unit_id|asset_id|equipment_class), version, effective_from/to, rule jsonb
  -- {stateSignalId | rateSignalId, digitalMap:{name→state}, thresholds:{stopBelow, reducedBelow, runAbove, hysteresis}, debounceSeconds 5, microStopSeconds 60, restartConfirmSeconds 10, maxStaleSeconds | staleFactor 3, monitorOutsideSchedule bool}
equipment_state_segments: id, tenant_id, unit_id, asset_id null, state enum(running, stopped, reduced_rate, idle, changeover, unknown), start, end null, quality enum(confirmed, provisional, estimated), rule_version_id, observation_refs jsonb (sample ids), created_at
  EXCLUDE USING gist (tenant_id WITH =, coalesce(asset_id, unit_id) WITH =, tstzrange(start, end, '[)') WITH &&)   -- non-overlapping per scope
event_impacts: id, tenant_id, event_id, impacted_unit_id, mode enum(none, full_stop, fractional, measured), fraction numeric(9,8), effective_from/to, evidence jsonb, rule_version
unit_impact_rules: id, tenant_id, asset_id, unit_id, mode, fraction, effective_from/to, version   -- standby/parallel trains
impact_occurrences: id, tenant_id, unit_id, start, end null, primary_event_id, primary_timing_source enum(source_event, derived_state, manual), state enum(auto, reviewed, ambiguous)
cause_allocations: id, tenant_id, occurrence_id, segment_start, segment_end, event_id, share numeric(9,8), precedence enum(manual, source_impact, rule, unclassified), approved_by null
  CHECK share between 0 and 1 ; Σ share per (occurrence, segment) = 1 enforced by service + deferred trigger
source_authority_policies: id, tenant_id, unit_id, product_id null, measurement enum(output, state, rate), primary_signal_id | primary_source enum(pi_output_ef, pi_counter, mqtt, kafka), fallback jsonb {conditions, signal}, cadence_seconds, conflict_tolerance numeric, override_role, version, effective_*
source_segments: id, tenant_id, policy_id, start, end, active_source, reason (fallback banner)
```
**State engine (worker, consumes `Normalized` measurements for state/rate signals)**
- `StateMachine.apply(observation)` per scope: candidate transition on threshold/digital change → confirmed after `debounceSeconds` (stop) or `restartConfirmSeconds` (run) with `effectiveStart = firstQualifyingObservation`; failed confirmation → observation only (DT02). Stale (> `maxStale`) or bad quality → close current segment with `quality=provisional` end and open `unknown` (DT04). Recovery after unknown: `estimated` end allowed with review item.
- `SegmentWriter` keeps `equipment_state_segments` non-overlapping; segments outside scheduled time flagged `outside_schedule=true` (calendar from 2.1; before that all time is "scheduled").
- `DerivedEventBuilder`: `stopped` segment ≥ `microStopSeconds` → canonical event `physical_type=downtime, source_kind=derived, oee_component=availability`; `< microStopSeconds` → `slowdown`/micro-stop event with `oee_component=performance` (DT03); `reduced_rate` → `slowdown` with measured impact; events carry `rule_version` and observation refs; open while segment open (end null).
- Provisional vs confirmed: event revisions `kind=system` mark `quality`.

**Impact and correlation**
- `ImpactResolver`: asset event → `event_impacts` per `unit_impact_rules` (default full stop when the asset is the unit's only train; `none` when standby exists); `measured` mode uses rate signal evidence.
- `OccurrenceCorrelator`: when a source event (PI EF) and a derived stop overlap on the same unit within tolerance → one `impact_occurrences` row, `primary_timing_source` per policy (default derived state if present else source event), relation `correlated_with` with confidence; ambiguous (multiple candidates) → `state=ambiguous` review item (SRC02). Downtime union (1.1) and accounting (2.5) consume occurrences, not raw events, so dual sources never double count.
- `CauseAllocator`: for each overlap segment on a unit, allocate shares by precedence manual → source impact → rule → unclassified; weights sum to 1; conflicting peers flagged (DT07, T03 "primary-cause allocations total 5400 s").

**Authority**
- `AuthorityService.resolve(unit, product, measurement, interval)` → active source per `source_segments`; fallback when primary stale/bad beyond `conflict_tolerance` → new segment + banner event `SourceFallbackActivated`; return to primary reconciles overlap (choose primary, log conflict) before promoting actuals (SRC01, T12).

**API v2**: `GET/POST /state-rules` (+ `POST /state-rules/preview {signalId, from, to}` → segments/events the rule would produce — DT01 "tested preview"), `GET /equipment-state-segments`, `GET/POST /unit-impact-rules`, `GET /impact-occurrences`, `POST /impact-occurrences/{id}/resolve`, `GET/POST /source-authority-policies`.

## Tests
- **T11 source outage**: MQTT/Kafka source goes silent → after `maxStale` segment becomes `unknown`; no `stopped` segment or downtime event created; health `unavailable`.
- **T12 competing actuals**: PI output EF and MQTT counter for same window → policy selects one; conflict visible (`source_segments` + review); accounting input not doubled (asserted again in 2.4).
- DT fixtures: 3 s dip below stop threshold → no stop (debounce); 90 s stop → downtime event start at first qualifying sample, end at first recovery (confirmation not added); 45 s stop → micro-stop performance event; stale 5 min → unknown 5 min, known downtime lower bound reported.
- Overlap allocation: two asset stops 10–11 and 10:30–11:30 → occurrence 10–11:30; allocation shares per segment sum to 1 (T03 extension); arrival order permuted → identical allocation (property).
- Impact: asset with standby → `none`; without → `full_stop`; fractional rule → derate event.
- Correlation: PI EF 10:00–11:00 + derived stop 10:00:05–10:59:50 → one occurrence; two candidate EFs → ambiguous review.

## Definition of done
- Signals produce non-overlapping state segments and derived downtime/micro-stop events under versioned rules with preview; unit impact and cause allocation implemented; occurrences dedupe dual sources; authority policy enforced; T11 T12 and DT fixtures green.

## Decisions / risks
- Equipment-class rule defaults are commissioning inputs (DT02); shipped defaults are configuration.
- Until calendars (2.1) exist, "outside schedule" is false everywhere; the flag is recomputed when calendars land.
- `btree_gist` exclusion constraint is the simplest guarantee of non-overlap; if partitioning is needed later, move the guarantee to the service with serialized writes per scope.
