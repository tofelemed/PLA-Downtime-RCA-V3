# 1.7 PI actuals — signals, counters, rates, output event frames

**Status:** ⬜ not started · **Epic:** P1 E05 · **Spec:** PI07–PI09, ACT02–ACT04 (engine rules), §14.2 `signals`, `measurement_samples`, §5.1 measurement identity, I11 · **Tests:** T25 T26 T27 (engine); persisted period results in 2.4 · **Depends on:** 1.5, 1.6

## Goal
Ingest production measurements from PI — recorded values, digital states, rates, totalizers and Production Output event frames — as versioned samples bound to typed signals, and implement the pure quantity engine (counter deltas with reset/rollover, rate integration, incremental output) that 2.4 will run per period.

## Spec requirements covered
- PI07 recorded values, digital states, rates, counters, output EFs; streams/streamsets recorded + summaries; capability per endpoint.
- PI08 stream updates only where supported; historical recovery independent; lost markers → re-register + bounded backfill.
- PI09 totalizer delta with reset/rollover; rate integration by configured interpolation and timebase; output EF counted once; PI `Total` summaries only after validating basis — never on cumulative counters.
- Per-signal config: semantic type, canonical unit, boundary interpolation, max gap, reset behaviour, rollover modulus, expected range, cadence, quality policy. Missing endpoints/undocumented resets → exception not fabricated delta.
- ACT02 counter split at resets/rollovers/meter changes/campaigns; negative delta not production. ACT03 rollover `M − a + b` if credible; reset without readings → unresolved; linear interpolation only when certified. ACT04 rate integration step/linear; timebase → seconds; persist method and excluded bad intervals.
- §5.1: measurement identity = signal + sample timestamp + upstream sequence/revision.

## Current implementation (verified)
- No server-side time-series ingestion (I11). `historian_tags` is a CRUD tag catalog (`webId, tagName, tagPath, category, uom, dataType, updateInterval, thresholds, config`). `historian-history` stores query history. Browser `PIHistorianProvider` supports recorded/interpolated/plot/summary for display only.
- Output quantities only via `Production Output` EFs mapped to `quantity`/`defectiveQuantity` (`decimal(10,2)`).

## Target design
**Schema (migration `0007-signals`)**
```
signals: id, tenant_id, connection_id, source_binding jsonb (webId/path or topic), unit_id, asset_id null, product_id null,
  semantic_type enum(rate, counter, state, quality, level, output_increment, other), canonical_uom, rate_timebase enum(s, min, h, d) null,
  interpolation enum(step, linear) default step, max_gap_seconds int, reset_policy enum(none, known_instant, detect_drop), rollover_modulus numeric(24,8) null,
  expected_min/max numeric(24,8), cadence_seconds int, quality_policy jsonb, is_authority bool, effective_from/to, version
measurement_samples (PARTITION BY RANGE (observed_at), monthly): id, tenant_id, signal_id, observed_at, value numeric(24,8) | state_name text | state_value int, quality enum(good, uncertain, bad, missing), raw_id, source_revision text, inserted_at
  UNIQUE (signal_id, observed_at, source_revision)   -- versioned correction for same logical sample
signal_backfill_runs: id, signal_id, from, to, state, reason
```
**Adapter extension (`PiWebApiAdapter`)**
- Job kinds: `pi-recorded-poll` (`/streams/{webId}/recorded?startTime&endTime&boundaryType=Outside&maxCount` paged; or `/streamsets/recorded` for many signals), `pi-summary-poll` (only for `rate` signals and only with `calculationBasis=TimeWeighted`, `summaryType=Total`, unit conversion validated — PI09), `pi-stream-updates` (channels where supported; marker loss → re-register + backfill from last durable sample).
- Each sample → envelope `kind=measurement` → `IntakeService.accept` → `measurement_samples` (duplicate = same signal/time/revision; corrected archive value = new revision).

**Quantity engine** `src/domain/actuals/` (pure, decimal.js):
- `counterDelta(samples, signal, window)` → `{quantity | null, segments[], exceptions[]}`: boundary readings by `interpolation` (linear only if `signal.interpolation=linear`), splits at detected drops: `reset_policy=known_instant` with pre/post readings → sum of deltas; `detect_drop` with `rollover_modulus` → `M − a + b` when implied rate ≤ `expected_max` (T26), else `exception(rate_implausible)`; drop without modulus/readings → `null` + `exception(reset_unresolved)` (T27); gaps > `max_gap_seconds` → `missing` coverage; never negative.
- `integrateRate(samples, signal, window)` → step or linear integration, `value × Δt / timebaseSeconds`, bad-quality intervals excluded and reported; method persisted (T25: 120 t/h × 30 min = 60 t).
- `outputEvents(events, window)` → Σ incremental quantities of `production_output` events whose timestamp ∈ window, once per source identity; spanning events need distribution (2.4).
- Coverage: `coverageRatio = observedSeconds / windowSeconds`, `measured` vs `estimated` split (ACT05 inputs).

**API v2**: `GET/POST /signals`, `POST /signals/{id}/preview {from,to}` → engine result with samples used (UX06 "preview quantities, units and times"), `POST /signals/{id}/backfill`.

## Tests
- **T25** unit: constant 120 t/h for 30 min, step and linear → 60 t; method + conversion recorded.
- **T26** unit: 995 → 5, modulus 1000 → 10; with `expected_max` lower than implied rate → exception, quantity null.
- **T27** unit: 1000 → 10, no reset time/readings → `null`, `reset_unresolved`; never 990/1010.
- Integration: simulator serves recorded values with an archive correction → second revision stored; preview returns both coverage and exceptions; summaries job refuses `counter` signals (422).
- Property: counter engine never returns negative; integration of zero-rate = 0.
