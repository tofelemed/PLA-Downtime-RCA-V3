# 1.3 Hierarchy mapping and code libraries

**Status:** 🧪 implemented 2026-10-08; unit + integration green (T05, T18 and companions); CI run and backfill on the data host pending · **Epic:** P1 E03 (+G06) · **Spec:** ING03 mapping priority, ING04 typed versioned attribute mappings, §3.2 distinct code libraries + failure code groups, §14.2 `source_mappings`, `reason_codes`, `impact_codes/oee_codes`, `failure_code_groups`, `loss_category_defs`, NFR01 no global code lists · **Tests:** T05 T18 · **Depends on:** 0.4

## Goal
Make source→plant mapping deterministic and typed, and make the code libraries tenant-scoped, hierarchical and versioned so events, losses and KPIs can reference a stable code version.

## Spec requirements covered
- ING03: priority exact source ID → exact normalized path → explicit ordered pattern → approved AF binding; normalize separators on both sides; define escaping/case/precedence; ambiguous → quarantine; asset mapping derives effective parent unit; cross-tenant parents rejected; **no substring reason assignment in production**.
- ING04: attribute mappings typed and versioned; tenant overrides merged **field by field**; UI uses the same field catalog as validation; digital states keep Name + Value; TimeSpan parsed only under explicit duration mapping with unit; timestamps authoritative over supplied durations (conflict → quality exception).
- §3.2: reason / impact / OEE libraries distinct, mapped by versioned rules with visible overrides; GE impact codes (OTSD, OTDD, RMDD, RMSD, RPDD, RPSD, TADD) preserved where required; failure class/problem/cause/remedy hierarchy separate.
- §14.2: `reason_codes` with `parent_id, path, active interval, defaults, version`, unique tenant/code/version, no cycles; `loss_category_defs` replaces free text.
- NFR01: no global code lists.

## Current implementation (verified)
- `source_hierarchy_mappings`: exact → glob → **substring path containment** (loose, forbidden by ING03) → connection default (never reached); `matchesPattern` normalizes `\` only in the pattern (I7); asset target yields no `unitId` and blocks `af_bindings` fallback (I6).
- Attribute mapping: backend defaults in `pi-event-mapper.ts`, frontend defaults in `src/services/pi/PIMapper.ts` disagree (`reasonCode` vs `reasonCodeId`, `goodQty`); override replaces whole template map (I10); enumeration objects stringified to `[object Object]` (B7/I4); `Number(val)` on TimeSpan → NaN.
- Code resolver resolves text codes by exact then **substring** match (forbidden in production by ING03).
- `reason_codes.parentId` commented out — tree UI not persisted (B12). `impact_codes`, `oee_codes`, `reason_codes`, `units`, `products` have **globally unique `code`**. Loss category = hard-coded list in `EventHub.tsx`.

## Target design
**Schema (migration `0004-mappings-and-codes`)**
```
source_mappings           (replaces source_hierarchy_mappings; old table kept read-only until 3.10)
  id, tenant_id, connection_id FK, match_kind enum(exact_id, exact_path, pattern, af_binding),
  match_value text, normalized_value text, precedence int, target_type enum(unit, asset), target_id uuid,
  effective_from, effective_to, version int, is_active, description
  UNIQUE (tenant_id, connection_id, match_kind, normalized_value, version)
attribute_mapping_versions
  id, tenant_id, connection_id, template_name, version, field_rules jsonb  -- [{sourceAttr, targetField, type: number|string|bool|digital|duration|timestamp, unit?, required?}]
  effective_from, effective_to, created_by
code_versions pattern applied to reason_codes, impact_codes, oee_codes:
  reason_codes: + parent_id FK (same tenant), path ltree/text, level int, version int, effective_from/to, default_oee_component, default_schedule_class, default_impact_code_id
  UNIQUE (tenant_id, code, version); drop global UNIQUE(code)  [same for impact_codes, oee_codes, units.code, products.code → (tenant_id, code)]
  CHECK no cycle: enforced by trigger or service (path must not contain own id)
failure_code_groups: id, tenant_id, group_kind enum(class, problem, cause, remedy), code, name, parent_id, version, effective_*
loss_category_defs: id, tenant_id, code, label, parent_id, report_order, effective_from/to, version
code_mapping_rules: id, tenant_id, rule_kind enum(reason_to_oee, reason_to_schedule_class, reason_to_impact, impact_to_valuation), source_code_version_id, target..., version, effective_*
```
**Field catalog** `contracts/event-field-catalog.json`: every mappable target field with type, unit expectations and which templates allow it (generated from the v2 event DTO; validated in a test so backend and UI cannot drift — fixes I10).

**Mapping engine** `SourceMappingService.resolve(connectionId, {sourceId, sourcePath, afElementWebIds[]})`:
1. exact `sourceId`; 2. exact `normalize(path)`; 3. patterns ordered by `precedence` (glob with documented escaping; case-insensitive; separators normalized to `/` on **both** sides); 4. approved AF bindings (`af_bindings`) by WebId, then by ancestor WebIds (walk up the supplied element path). Multiple hits at the same tier → `MappingAmbiguous` → quarantine (1.5). Asset target → `unitId = asset.unit_id` (must be same tenant). Returns `{unitId, assetId, mappingId, version}`.

**Attribute mapper** `AttributeMappingService.map(templateName, attributes[], version)`: typed conversion per rule; digital → `{name, value, isSystem}` stored in `source_facts`, and `name` used for code lookups; `duration` type requires `unit` (`seconds|minutes|hours|timespan`) and parses `hh:mm:ss`; if both timestamps and duration exist and disagree → quality exception recorded, timestamps win. Tenant overrides merged per field over defaults.

**Code resolver**: exact `code` or exact `name` (case-insensitive) within tenant and effective date; substring matching removed (kept only behind `DEV_FUZZY_CODES=true` for demo seeding). Unresolved → quarantine with suggestion list.

**API v2**: `GET/PUT /api/v2/source-mappings/{id}` (+ list, `POST /source-mappings/preview {sampleIdentifiers[]}` → resolution + ambiguity report, §15.2); `GET/POST /api/v2/reason-codes` (tree, `?parentId`, `?asOf`), `POST /reason-codes/{id}/retire`, same for impact/oee/failure groups/loss categories; `GET /api/v2/field-catalog`.

## Decisions / risks
- Dropping the global unique on `code` changes v1 behaviour for duplicate codes across tenants (none exist today — verify in 0.1 data inventory).
- `ltree` extension for `path` is convenient but adds a Postgres extension dependency; plain text path with trigger is the fallback.
- **Deviations (8 Oct 2026, implementation):**
  - **Code versions:** a code keeps one row with a stable id and its current `version`; every change appends an immutable row to one `code_versions` table (`library` + polymorphic `code_id`). Uniqueness is UNIQUE(tenant_id, code) per library (failure groups: per kind) instead of (tenant_id, code, version): a row-per-version design would break the parent FKs of a tree at every parent change. `event_coding.reason/impact/oee_code_version_id` → `code_versions` (the 1.2 follow-up FKs).
  - **Mapping rules** reference the stable `source_code_id` and are append-only; the rule in force is the highest version whose `effective_from` is not after the instant (`effective_to` exists, unused). A new code version therefore keeps its rules; old rule rows never change (T18).
  - **`source_mappings`** are edited in place (`version` counts edits, `row_version` is the ETag) — no per-version history rows. `connection_id` has no FK (ids of OPC UA/MQTT/... connections live in other tables); null = any connection. Uniqueness = two partial unique indexes over active rules (Postgres NULLs; TypeORM 0.3.25 has no `NULLS NOT DISTINCT`).
  - **`af_bindings` are read live** as tier 4 (the spec's "approved AF bindings") instead of being copied: copies would go stale while the v1 AF binding UI keeps writing that table. v1 hierarchy mappings stay writable through v1 and are mirrored (expand step); mirrored rows are read-only in v2 (409 `LEGACY_MAPPING`).
  - **Ancestor walk:** the PI bridge supplies the primary element and `RefElementWebIds`; fetching ancestor WebIds from PI needs extra calls and is left to 1.6. The preview accepts a full chain.
  - **Quarantine before 1.5:** unplaceable frames go to `unmapped_events` with `status`, candidates and diagnostics. Unresolved/ambiguous codes do **not** quarantine the event: it is created uncoded, the diagnostic (with suggestions) is kept in `source_facts.mappingDiagnostics` and returned in the pull response; `DURATION_MISMATCH` (timestamps win) is recorded the same way until the 1.5 quality-exception store exists.
  - **Field catalog names:** code fields are source facts `reason`, `impactCode`, `oeeCode` (digital or text, resolved to ids); the supplied duration is `suppliedDurationSeconds`. Legacy targets (`reasonCodeId`, `reasonCode`, `goodQty`, `scrapQty`, `duration` → minutes) are translated. `SOURCE_FIELDS` gained these attribute facts (stored in revisions only; structured values compare by canonical JSON).
  - The mapping profile is loaded once per pull at pull time (not per frame time). `DEV_FUZZY_CODES` was not built: substring matching is gone everywhere.
  - Tenant-less legacy codes are no longer accepted as event references (NFR01); existing rows are left untouched (D11).
  - `loss_category_defs.name` holds the label (uniform library shape); the hard-coded list in `EventHub.tsx` is unchanged (3.x).
  - Writes need `master_data_admin`/`manager_approver` (codes) or `integration_admin`/`manager_approver` (mappings, attribute rules) — engineering default in DECISIONS.md §D.
  - Contract additions (flagged): optional `details` in the API error envelope (409 reference counts); v1 PI pull response gains `diagnostics`; v2 event view gains `classificationBasis` and `impactCodeId`.
  - Size rules: DI constructors of `PiFrameIngestService` (7), `PIEventPullService` (7, was 13) and `ProductionEventsV2CommandService` (5) exceed 4 parameters; the migration is 478 lines (generated DDL); `production-event.entity.ts` +5 lines.
- **Open (follow-up):** v1 code CRUD does not append `code_versions` (a baseline is written lazily on the first v2 change; codings of such codes carry a null version id until then); `impact_to_valuation` rules are stored but consumed only in 2.6; ancestor WebIds from PI (1.6); quality exceptions and quarantine move to 1.5; mapping/code UIs in 3.7/3.8.
