# 1.5 Durable intake core — raw store, jobs, inbox/outbox, quarantine, replay

**Status:** 🧪 2026-10-08 (implemented, green locally; CI run open) · **Epic:** P1 E04 Durable intake · **Spec:** FND01–FND04, §5.1 envelope, ING01, ING02 job lifecycle, ING05 quarantine, ING07 adapter interface, §14.2 `integration_connections`, `ingestion_jobs`, `raw_observations`, `source_objects`, `ingestion_exceptions`, `inbox`/`outbox`, API04, G03 · **Tests:** T06; T10 (inbox uniqueness); replay invariance property test; crash recovery · **Depends on:** 0.3, 0.4

## Goal
Build the source-neutral intake pipeline every connector plugs into: durable raw retention before acknowledgement, idempotent business effects, leased jobs with checkpoints, a quarantine with replay, and a transactional outbox — so PI, MQTT and Kafka share one contract and one recovery model.

## Spec requirements covered
- FND01 retain before ack/checkpoint; FND02 at-least-once + idempotent (inbox/outbox); FND03 immutable result sets (consumed by 2.5); FND04 event/received/processing time, out-of-order normal, 120 s default lateness.
- §5.1 envelope (identity, times, location, values, quality, provenance, source controls); logical identity = tenant + connection + source object; content hash when no version; conflict instead of overwrite when order unprovable.
- ING02: leased job, heartbeat, committed checkpoint, last observation time, retry count, health; start/pause/drain/resume/replay/stop audited; stop finishes in-flight work; multiple scopes/templates per tenant.
- ING05: quarantine with raw payload, error code, connection, first/last seen, retry count, owner; resolution = preview, validate, mapping revision, replay; replay references original identity.
- ING07: adapter interface (validate config, discover capabilities, test, discover metadata, read/subscribe, checkpoint, pause/drain, replay or declare unsupported, health, close).
- API04 jobs; §15.2 `/connections`, `/ingestion-jobs/{id}/{action}`, `/connections/{id}/replays`, `/ingestion-exceptions`.

## Current implementation (verified)
- PI only: `pi_connections` (password AES-GCM), `pi_sync_jobs` (`jobConfig` JSON), `pi_sync_watermarks` (always advanced), `pi_events` (raw EF JSON per WebId, no revisions), `unmapped_events` (quarantine-like, PI-specific, no replay). In-memory run lock. No raw store for other sources, no outbox, no inbox. `data_sources`, `streaming_*`, `connectivity` connection tables are CRUD-only.
- Scheduler in API process (moved to worker in 0.3).

## Target design
**Envelope** — `contracts/canonical-event.schema.json` (JSON Schema 2020-12) with `kind: interval_event | measurement | state | output_event | retraction`, fields per §5.1; TypeScript types generated; validated with ajv at the adapter boundary.

**Schema (migration `0006-intake-core`)**
```
integration_connections: id, tenant_id, source_type enum(pi_web_api, mqtt, kafka, ...), display_name, endpoint_config jsonb (no secrets), secret_ref text, capabilities jsonb, config_version int, is_active
  -- pi_connections migrated in: secret_ref points to encrypted secret row (secrets table or vault ref)
ingestion_jobs: id, tenant_id, connection_id, scope jsonb (templates, elements, topics…), state enum(created, running, paused, draining, stopped, failed),
  lease_owner text null, lease_expiry timestamptz null, heartbeat_at, committed_cursor jsonb, last_observation_at, last_success_at, retry_count, last_error text, cadence jsonb, recovery jsonb, version
  UNIQUE (connection_id, scope_hash) WHERE state <> 'stopped'
raw_observations (PARTITION BY RANGE (received_at), monthly): id, tenant_id, connection_id, message_id text, source_identity text, source_revision text null, content_hash text,
  kind, event_time, received_at, processing_at null, payload jsonb | payload_ref text, payload_size, quality jsonb, source_cursor jsonb, mapping_version int, correlation_id, replay_run_id null
  UNIQUE (tenant_id, connection_id, message_id); INDEX (tenant_id, source_identity, received_at)
source_objects: id, tenant_id, connection_id, source_object_id text, kind, canonical_event_id uuid null, signal_id uuid null, latest_revision text, latest_hash, first_seen, last_seen, state enum(active, retracted, deleted_confirmed)
  UNIQUE (tenant_id, connection_id, source_object_id)
ingestion_exceptions: id, tenant_id, connection_id, raw_id, error_code enum(unknown_template, unknown_code, unknown_unit, mapping_ambiguous, schema_invalid, unit_conflict, duration_conflict, ...), detail jsonb, state enum(open, resolved, irrecoverable), owner_id, first_seen, last_seen, occurrences, resolution jsonb, replay_run_id
replay_runs: id, tenant_id, connection_id, from, to, scopes, reason, dry_run, state, counts jsonb, requested_by
inbox: delivery_key text PK, tenant_id, scope, type, received_at, processed_at
outbox: id, tenant_id, aggregate_type, aggregate_id, type, version, payload jsonb, scope, state enum(pending, published, failed), attempts, next_attempt_at, created_at
  INDEX (state, next_attempt_at)
```
**Services**
- `IntakeService.accept(envelope)` (one transaction): validate schema → insert `raw_observations` (duplicate `message_id` → record duplicate counter, return `duplicate`) → upsert `source_objects` (identical hash → `duplicate_content`; changed → `revision`; order unprovable → `conflict` exception) → enqueue normalization (`outbox` `RawAccepted`). **Ack/checkpoint only after commit** (FND01).
- `NormalizationService` (worker, consumes `RawAccepted` via inbox): mapping (1.3) → canonical event revision (1.2) / measurement sample (1.7) / state observation (1.10); failures → `ingestion_exceptions` with `error_code`; a quarantined record still counts as accepted for cursor purposes but marks `completeness=false` for affected scopes (PI04).
- `JobRunner` (worker): claims due jobs with `UPDATE … SET lease_owner, lease_expiry WHERE lease_expiry < now() RETURNING` (one lease per connection+scope), heartbeats, calls adapter `read(cursor)`; commits `committed_cursor` only after all returned records are durably accepted or quarantined; `pause/drain/stop` set state and let in-flight page finish; audit each transition.
- `OutboxRelay` (worker): publishes pending rows to Kafka (1.9) or, before Kafka exists, to the in-process event bus; marks `published`; exponential backoff; emits once per outbox id (API05).
- `Adapter` interface (ING07) in `src/intake/adapters/adapter.interface.ts`; `capabilities` declares replay/corrections/deletions/quality/timestamps/sequence.
- `ReplayService`: `POST /connections/{id}/replays` → `replay_runs` → adapter `replay(from, to, scopes)`; each re-emitted envelope carries `replayRunId` and the **original** `message_id`/identity so `IntakeService` recognises duplicates (T06: replay twice → one canonical event).

**API v2**: `GET/POST /connections` (redacted), `POST /connections/{id}/test`, `GET /connections/{id}/discover`, `POST /connections/{id}/jobs`, `POST /ingestion-jobs/{id}/{start|pause|resume|stop}`, `POST /connections/{id}/replays`, `GET /ingestion-exceptions`, `POST /ingestion-exceptions/{id}/resolve`, `GET /jobs/{id}`.

## Decisions / risks
- Secrets: R1 keeps AES-GCM encryption in a `secrets` table with `secret_ref`; vault integration is a later swap behind the same interface (§4.2).
- Payloads > 1 MiB → `payload_ref` to local object storage (MinIO in Compose or filesystem volume) per KF04.
- Partitioned table uniqueness: `(tenant_id, connection_id, message_id)` includes the partition key only if `received_at` is added; use a separate identity registry table (`raw_identities`) for the global unique (DB03 last sentence).

- **Deviations / decisions (8 Oct 2026, implementation):**
  - **Raw store:** `received_at` is the intake commit time (partition key, never the adapter clock); the envelope's own `receivedAt`/`observedAt` stay in the payload and `event_time`. A repeated message id adds no raw row (`raw_identities.duplicate_count`). Payloads are always inline: the `payload_ref` column exists, object storage above 1 MiB (KF04) is left to 1.9. Rows are immutable (trigger); retention (dropping partitions) is not scheduled yet.
  - **Ordering (§5.1):** the source observation time decides; a tie is broken only by numeric source revisions (sequence/offset). A tie that cannot be ordered is `conflict` → `order_conflict` exception, never an overwrite; an older version is `stale` (kept raw, not applied). `content_hash` excludes delivery fields (message id, times, provenance).
  - **PI as a source:** PI frames carry no version, so `messageId = WebId:sha256(frame + attributes)` and `observedAt` = read time: an unchanged re-read is a duplicate delivery (no raw row), a changed frame a newer revision. A redelivery of a quarantined object retries its normalisation (exception `occurrences` = retry count); this keeps the pre-1.5 behaviour where the next pull places a frame once its binding exists.
  - **PI pull path:** `PIEventPullService` → `PiIntakeBridge`: envelope → `accept` → normalised **inline** under the inbox key the relay uses, so the v1 response keeps its created/updated/unmapped counts and the later relay delivery is a no-op. `pi_events` (v1 raw table) is still written; `autoCreateProductionEvents: false` bypasses intake (v1 semantics). The v1 `PISyncSchedulerService` keeps running `pi_sync_jobs`; new leased jobs use `PiWebApiAdapter` (time window + `startIndex` paging; certified in 1.6).
  - **Quarantine:** unplaceable/ambiguous PI frames go to `ingestion_exceptions` (`unknown_unit`, `mapping_ambiguous`, `mapping_invalid_target`) **and are still mirrored** into `unmapped_events`, so the v1 screens keep working (mirror, not move). A crashing normaliser is quarantined as `processing_failed` (and reported as a frame error by the v1 pull).
  - **Replay** re-delivers the **latest retained version** of each source object in scope (not every historical raw row) with the original message id and the run id; each replay delivery adds a raw row (`outcome = replayed`, `original_raw_id`). A replay never changes the latest version. Re-reading the source (`replayRead`) is optional per adapter and not implemented for PI.
  - **Inbox:** `runOnce` inserts the key and runs the effect in one transaction. The normaliser's effects use their own transactions (event revision service) and are idempotent (source identity + fact dedupe), so a crash between effect and inbox commit only re-runs a harmless effect. Key = `normalize:<outbox id>`; normalising a raw version that is no longer the latest is skipped (`superseded`).
  - **Outbox relay** publishes in id order under `FOR UPDATE SKIP LOCKED`; a failed row backs off (2 s × 2^n, cap 10 min) and holds back later rows of its aggregate; after `OUTBOX_MAX_ATTEMPTS` (12) it becomes `failed` (dead letter). The realtime broadcast to browsers stays a direct post-commit call (the worker has no socket server); the outbox is the durable path for Phase 2 consumers. No Kafka transport yet (1.9, D10).
  - **Bulk jobs (1.4 follow-up):** `bulk_jobs` gained `lease_owner`/`lease_expiry`/`attempts`; each chunk's record and lease heartbeat commit in the chunk's own transaction, so the job of a dead worker is reclaimed after `BULK_JOB_LEASE_SECONDS` (120) and continues after its last recorded chunk.
  - **API shapes:** `POST /ingestion-jobs/{id}/{action}` also accepts `drain`; added `GET /ingestion-jobs`, `GET /ingestion-jobs/{id}/transitions`, `GET /ingestion-exceptions/{id}` (with the raw delivery) and `GET /replay-runs/{id}`; replays answer 202 `JobAccepted` pointing at `/api/v2/replay-runs/{id}` (bulk jobs keep `/jobs/{id}`). `POST /connections/{id}/test` and `GET .../discover` have no side effect and are not `@Idempotent`. Writes need `integration_admin`/`manager_approver` (DECISIONS §D). List cursors compare timestamps truncated to milliseconds (`now()` columns carry microseconds).
  - **Types:** the TypeScript envelope types are hand-written next to the checked schema copy (no generator dependency); a unit test keeps their property names equal to the schema's.
  - **Size rules:** DI constructors of `IntakeQueriesV2Service` (5 repositories) and `PiIntervalHandler` (5) exceed 4 parameters, like the existing services; new functions ≤ 40 lines, files ≤ 400 lines.
- **Open (follow-up):** object storage for large payloads and raw retention (1.9 / ops); RCA auto-create still writes `rca_id` directly (1.2 open item, not yet through a revision/outbox); `completeness=false` for quarantined scopes (PI04) waits for the period engine (2.x); PI deletion detection and ancestor WebIds (1.6); metrics export (3.12); dev DB `proact` is still at `EventIntervalModel` (the API applies the four pending migrations on next boot).
