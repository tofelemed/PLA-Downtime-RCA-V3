# 1.1 Event interval model and classifications

**Status:** ⬜ not started · **Epic:** P1 E03 · **Spec:** §3.2 four classifications, §3.3 time conventions, DT05 overlap/clipping, DT08 manual create, DT11 three state dimensions, DB01–DB03, G01 · **Tests:** T01 T02 T03 T29 (+T42 advisory) · **Depends on:** 0.3, 0.4

## Goal
Make a production event a correct interval: UTC half-open, open end = null, duration derived in seconds, classified on four independent axes, with separate physical/coding/RCA states — and provide the interval algebra (clip, union, split) the downtime and accounting engines will use.

## Spec requirements covered
- §3.3: `timestamptz` UTC; half-open ranges; `durationSeconds` derived at full precision; open event `endTime null` + server `elapsedAsOf`; decimals `numeric(24,8)` with unit.
- §3.2: physical type (downtime / slowdown / quality loss / production output / advisory), schedule class (planned / unplanned / external / unknown), OEE component (availability / performance / quality / idle / none), cause code. IOW/SOL/APM/FailureWO are **advisory** until linked (T42).
- DT05: clip to window and schedule; split at shift/day/campaign/rate/schedule boundaries; unit downtime = union of eligible intervals (T03 90 min not 120); asset totals not additive.
- DT08: manual create validation; duration-only entry computes end; conflicting end/duration rejected; zero-duration stop cannot be downtime.
- DT11: physical state open/closed/superseded/retracted; coding state uncoded/coded/reviewed; RCA state none/required/linked/completed; legacy labels through an adapter.
- DB02: checks `end > start`, enums, nonnegative quantities. DB03: indexes tenant/unit/start, tenant/asset/start, tenant/type/start, open-event partial index.

## Current implementation (verified)
- `production_events`: `start_time` NOT NULL, `end_time` nullable, `duration decimal(10,2)` with unknown unit, never derived; manual events never set it (B8); PI open frames stored as `9999-12-31` (B6); `event_type` single axis; `status` free string set by client; `tenant_id` varchar(36); no indexes; `quantity/cost decimal(10,2)`.
- Status rules live in the browser (`EventHub.tsx`, `localStorage`).
- Reporting assumes `duration` is minutes; Event Hub detail labels it hours.

## Target design
**Schema (expand migration `0002-event-interval-model`)**
```
production_events  (existing table, new columns)
  physical_type        enum(downtime, slowdown, quality_loss, production_output, advisory)  -- derived from legacy event_type on backfill
  schedule_class       enum(planned, unplanned, external, unknown) default unknown
  oee_component        enum(availability, performance, quality, idle, none) default none
  impact_mode          enum(none, full_stop, fractional, measured) default none
  impact_fraction      numeric(9,8) null  -- 0..1 when fractional
  physical_state       enum(open, closed, superseded, retracted)
  coding_state         enum(uncoded, coded, reviewed)
  rca_state            enum(none, required, linked, completed)
  duration_seconds     numeric(18,3) GENERATED ALWAYS AS (CASE WHEN end_time IS NULL THEN NULL ELSE EXTRACT(EPOCH FROM (end_time - start_time)) END) STORED
  quantity_uom         varchar(32) null ; quantity/cost widened to numeric(24,8)
  source_kind          enum(manual, source, derived, imported)
  canonical_id         uuid  -- stable business id; `id` stays PK; populated = id on backfill
  legacy_duration      numeric(10,2) null ; legacy_duration_unit_assumed varchar(8) null  -- MIG §18.2 "mixed duration units"
  tenant_id            -> uuid (type change via new column + backfill + swap, since v1 uses varchar)
CHECK (end_time IS NULL OR end_time > start_time)
CHECK (physical_type <> 'downtime' OR end_time IS NULL OR end_time > start_time)   -- zero-duration stop invalid
INDEX (tenant_id, unit_id, start_time), (tenant_id, asset_id, start_time), (tenant_id, physical_type, start_time)
PARTIAL INDEX (tenant_id, unit_id) WHERE end_time IS NULL
```
Legacy `status` column is kept and **maintained by the adapter** from the three states: `open`→Open; `closed+uncoded`→Coded? No — mapping table: `Open`=(open,*,none), `Coded`=(closed,coded,none), `RCA Required`=(*,*,required), `Investigating/In Progress`=(*,*,linked), `Closed/Completed`=(closed,reviewed,completed|none). The adapter is the only writer of `status` after this migration.

**Domain library** `src/domain/time/`
- `Interval {start: Date, end: Date|null}`; `clip(i, window)`, `union(intervals)`, `splitAt(i, boundaries[])`, `durationSeconds(i, asOf)`; all half-open, pure, property-tested (union is idempotent/commutative; Σ split parts = whole).
- `Duration` formatting lives in the API layer only (`durationSeconds` + display helpers).

**Services**
- `EventIntervalService.validateCreate(dto)`: start required; `end` xor `durationSeconds` (if both, must agree within 1 s else 422 `DURATION_CONFLICT`); end > start; downtime requires non-zero.
- `EventClassificationService.defaults(eventType, codes)`: legacy `eventType` → `physical_type`; IOW/SOL/APM/FailureWO → `advisory`, `oee_component=none`, `impact_mode=none` (T42: no automatic production loss).
- `UnitDowntimeService.unionForWindow(tenant, unitId, window, filter)` → union seconds, occurrence list, carry-in flags (feeds 2.7/3.3).
- `LegacyStatusAdapter.toLegacy(states)` / `fromLegacy(status)` for v1.

**API v2 (first real resource, replaces 0.4 reference)**
- `GET /api/v2/production-events` filters: `unitIds, assetIds, physicalTypes, scheduleClasses, oeeComponents, physicalStates, codingStates, rcaStates, reasonIds, from, to, isOpen, cursor, limit, sort`; overlap semantics; items include `durationSeconds`, `elapsedSeconds` (open, with `asOf`), `states`, `classifications`.
- `POST /api/v2/production-events` (DT08 body as §15.3 example) → 201 with ETag; `@Idempotent()`.
- `GET /api/v2/production-events/{id}`; `PATCH` (user fields only, `If-Match`).

**Backfill job** (worker, idempotent): set `physical_type` from `event_type`; `end_time = NULL` where `end_time >= 9999-01-01` (keep raw in `legacy_end_sentinel`); copy `duration`→`legacy_duration` with `unit_assumed='min'` where source is a seeder/PI mapping that documented minutes, else `null` + review flag (MIG §18.2); states from legacy `status`.

- **T02** unit+integration: create with PI sentinel (via 1.6 later, here via direct insert) → `end_time null`; `GET` at asOf 10:15 → `elapsedSeconds 900`; `duration_seconds` null.
- **T03** unit: union of 10–11 and 10:30–11:30 → 5400 s; per-asset 3600 each; occurrence count 2.
- **T29** unit: 05:50–06:20 split at 06:00 → 600 + 1200; one occurrence.
- **T42** integration: create IOW advisory → `oee_component none`, `impact_mode none`; downtime union for the unit unchanged.
- Validation: end ≤ start → 422; end and duration disagree → 422 `DURATION_CONFLICT`; zero-duration downtime → 422.
- Property tests for interval algebra.
- Legacy adapter round-trip for all v1 status labels.

## Definition of done
- Migration applied; backfill report committed; v2 event list/get/create/patch live with compound filters; `status` only written by adapter; T01 T02 T03 T29 T42 green; v1 e2e suite unchanged or improved.

## Decisions / risks
- Generated column for `duration_seconds` keeps every reader consistent; if TypeORM generated-column support is awkward, use a trigger — decide in step 1.
- `tenant_id` type change on a live table is the riskiest step; do it expand/contract across two migrations.
- Legacy `duration` inference: only seeders and PI mappings documented minutes; others flagged for review, never guessed (§2.3 last paragraph).
