# 1.8 MQTT adapter

**Status:** 🔄 steps 1–3 done (11 Oct 2026) · **Epic:** P1 E06 · **Spec:** MQ01–MQ05, FND01, ING07, §4.2 TLS, D09 · **Tests:** T09 T11 · **Depends on:** 1.5

## Goal
A certified MQTT intake path: durable append before acknowledgement, deduplication across reconnects, correct handling of retained messages and Last Will, typed payload mapping into the canonical envelope — feeding the same normalization, quarantine and state engine as PI.

## Spec requirements covered
- MQ01 MQTT 5 + 3.1.1 compatibility; broker endpoints, stable client id, TLS trust/client cert or approved auth, topic allowlist, QoS, keepalive, reconnect, session lifetime, payload mapping; topic text never replaces authenticated tenancy.
- MQ02 QoS 1 default, persistent sessions, application idempotency; retained message = stored state, not a new transition.
- MQ03 payload must carry event time + stable sequence/identity; preserve retained flag, boot/session id, sequence; missing timestamp → receive time with degraded flag; certified signals require event time.
- MQ04 verify client can delay ack until durable append; otherwise durable local gateway; spool sizing; LWT/keepalive → **source health unavailable**, not equipment stopped.
- MQ05 dedupe by source id + boot id + sequence; packet ids are not business identities; out-of-order via event-time processing; Sparkplug as optional certified decoder.

## Current implementation (verified)
- `connectivity/services/mqtt-client.service.ts` wraps the `mqtt` npm library (v5) and `broadcastConnectionData` over WebSocket only; nothing persisted; `mqtt.service.ts` test/browse paths simulated. `mqtt_connections` entity exists (connectivity module) with host/port/topics config.
- Mosquitto 2.1 running on this host (1883, 8883) — usable dev broker.

## Target design
**`MqttAdapter implements Adapter`** (`src/intake/adapters/mqtt/`)
- Config in `integration_connections.endpoint_config`: `brokerUrl`, `protocolVersion (5|4)`, `clientIdPrefix`, `tls {ca, cert, key refs}`, `auth {username, secretRef} | cert`, `topics[] (allowlist with wildcards)`, `qos (1)`, `keepalive`, `sessionExpirySeconds`, `cleanStart=false`, `payloadMapping` (schema id → field rules: `eventTimePath`, `sequencePath`, `bootIdPath`, `sourceIdPath`, `valuePath`, `unitPath`, `qualityPath`, `kind`), `identityStrategy enum(seq_boot, payload_hash)`.
- Connection with `manualAck: true` (mqtt.js supports manual acknowledgement for QoS 1/2); handler: parse → build envelope → `IntakeService.accept()` → **then** `client.ack(packet)`. If the chosen client cannot defer acks in some mode, use a durable local spool (append-only file/Postgres table) before ack and declare the configuration in `capabilities` (MQ04).
- Topic → tenant/connection binding comes from the connection; the topic path is used only for mapping (`source_mappings` `exact_path`/`pattern`), never for tenancy.
- Retained flag: `retain=true` messages produce `kind=state` envelope with `isRetained=true` and original `eventTime`; the state engine (1.10) may seed current state with staleness check but never opens a new stop at connect time (T09).
- Dedup key: `${sourceId}:${bootId}:${seq}` (or payload hash + eventTime when absent) as `message_id` → `raw_observations` unique.
- Missing event time → `receivedAt` with `quality.degraded=true`; signals marked `certified` reject such samples to quarantine.
- LWT topic or keepalive expiry → `SourceHealthChanged(unavailable)` → signals' staleness → `Unknown` segments (1.10), never `Stopped` (T11).
- Sparkplug B decoder optional module (protobuf, alias map, NBIRTH/NDEATH/DBIRTH, seq rollover) behind capability flag; not R1-blocking.
- Health: connected/disconnected, reconnect count, last message at, spool depth; exposed via job health.

**Payload mapping schema** `contracts/mqtt-payload-mapping.schema.json`; a default JSON mapping `{ts, seq, bootId, id, value, unit, quality}`.

## Tests
- **T09 MQTT replay** (integration with real broker): publish state messages; disconnect subscriber; broker redelivers QoS 1 duplicates and a retained old state on reconnect → one business observation effect; no new stop created at reconnect.
- **T11 source outage**: stop broker / LWT fires → source health `unavailable`; state engine produces `Unknown` (verified in 1.10), not `Stopped`.
- Durable-before-ack: crash handler after `accept()` commit but before ack → redelivery → duplicate recorded, single raw row effect; crash before commit → message redelivered and accepted once.
- Topic outside allowlist → rejected with explicit error (not accepted).
- Missing timestamp → degraded flag; certified signal → quarantine.
- MQTT 3.1.1 mode compatibility test.

## Definition of done
- MQTT messages flow into `raw_observations` → normalization → events/samples/states with no loss or duplication under reconnect; health semantics correct; certification evidence recorded; D09 defaults confirmed or noted.

## Decisions / risks
- If `manualAck` proves unreliable in the client version, the spool path becomes mandatory and "no-loss" is only claimed with it (MQ04).
- Broker session capacity is finite; document the commissioned outage window in the connection config.
