# PLA Next-Generation — Master Plan and Checklist

Implementation plan for `PLA_Next_Generation_Development_Specification.docx` (v1.0, 7 Oct 2026). Start with [SPEC_ANALYSIS.md](SPEC_ANALYSIS.md) for what the spec changes and why. [ENGINEERING_STANDARDS.md](ENGINEERING_STANDARDS.md) holds the performance and code-quality rules every sub-phase must meet (verified in 3.11). [STANDARDS_REFERENCE.md](STANDARDS_REFERENCE.md) lists the ISA/ISO/IEC/OASIS standards we align with and where. [DECISIONS.md](DECISIONS.md) is the fill-in decision register; Phase 1+ design waits for its answers or explicit "use default" ticks.

**This file is the single status board.** Update the checkboxes here *and* the step checklist inside the sub-phase file. A sub-phase is ✅ only when: all its steps are checked, its mapped acceptance tests (T-IDs) pass in CI, and the capability is demonstrated end to end.

Status legend: ⬜ not started · 🔄 in progress · 🧪 implemented, tests pending · ✅ done · ⛔ blocked (say why in the sub-phase file)

## Decisions recorded 7 Oct 2026 (see [DECISIONS.md](DECISIONS.md) §D)

- **Pilot scope:** plant **HDPE**, units `unit100`–`unit500`, timezone **Asia/Tehran**. Dev sizing = 1 plant, 5 units.
- **Connector order changed (D09/D10):** MQTT (1.8) and Kafka source adapter (1.9 source half) move to **after Phase 2** — they are built before Phase 3 analytics but after the accounting core. The outbox→Kafka internal transport in 1.5/1.9 stays in Phase 1 because realtime and accounting consumers need it.
- **Identity (D15):** Docker Compose + local JWT only in R1; OIDC/SSO dropped from 3.11, replaced by JWT hardening.
- **Demo data (A4):** new seeders on the real path replace the legacy seeders.
- Everything else: proposed defaults (ISO 22400 / ISO 14224 interpretations in [STANDARDS_REFERENCE.md](STANDARDS_REFERENCE.md)).

## Working rules

1. **Order:** 0.1 → 0.2 (parallel) → 0.3 → 0.4 → Phase 1 (1.1–1.7, 1.10 + internal transport) → Phase 2 → **1.8, 1.9 source adapter** → Phase 3. Within a phase, sub-phase files list their dependencies; parallel work is allowed where none exist.
2. **Expand-and-contract (MIG02):** add new tables/columns and v2 routes beside the old; switch the frontend by feature flag; retire old write paths only after reconciliation gates.
3. **Tests first for mathematics:** fixtures from §19 are written as failing tests before the engine code (T-IDs are the file names under `test/fixtures/`).
4. **No fabricated data in product code.** Demo data only via isolated seeders in a demo environment (UX03).
5. **Evidence:** when a sub-phase is marked ✅, add the commit hash and the CI run link to its file.
