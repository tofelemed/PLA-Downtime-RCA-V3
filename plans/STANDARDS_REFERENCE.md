# Standards Reference — what we align with and where

**Scope caveat (from the spec, §3.2 and KPI04):** GE impact codes and the reference presentations "do not establish compliance with a licensed benchmarking standard", and the reconciled OEE "is not a certification that a chosen plant policy complies with an ISO or SMRP standard". We **align definitions, vocabulary and data structures** with the standards below so results are explainable and comparable; we do not claim certification. Any compliance statement needs a separate assessment (NFR03).

| Standard | What it covers | What ProAct adopts | Spec IDs | Plan sub-phases |
|---|---|---|---|---|
| **ISA-95 / IEC 62264** (Enterprise–control integration) | Equipment hierarchy (enterprise → site → area → work center/unit → equipment), production schedule/performance, material/personnel models, operations event definitions | Hierarchy `tenant > organization > site > production unit > asset`; a *unit* is where production and capacity are measured; plan (schedule) vs performance (actuals) separation; reason codes labelled "ISA-95" today stay a tenant-managed hierarchy | §3.1, PLAN02, ACT01 | 2.1 (`sites`), 1.3 (reason tree), 2.3, 2.4 |
| **ISA-88 / IEC 61512** (Batch control) | Procedural/recipe model, campaigns, batches | *Campaign* as a time allocation of a unit to a product; joint-production *recipe* for shared capacity (PLAN05) | PLAN02, PLAN05, D14 | 2.3 |
| **ISO 22400-1/-2** (KPIs for manufacturing operations management) | Time model (planned busy time, actual production time, delay time, unplanned downtime), KPI definitions for availability, effectiveness/performance, quality ratio, OEE, with explicit numerators/denominators | Operational OEE uses the ISO 22400 time model: S = planned production time after approved exclusions, R = S − availability stops, ideal-time weighting for performance; every KPI stored as numerator/denominator; aggregation by summing terms, never averaging percentages | KPI01–03, AN03 | 2.7, 3.3, 3.6 |
| **TPM "six big losses"** (Nakajima; industry practice, not an ISO standard) | Breakdowns, setup/changeover, idling & minor stops, reduced speed, process defects, start-up rejects | Physical types downtime / slowdown / quality loss; micro-stops → performance; Changeover and Idle states; schedule class planned/unplanned/external | §3.2, DT01, DT03, KPI02 | 1.1, 1.10 |
| **ISO 14224** (Reliability and maintenance data for equipment) | Equipment boundaries and taxonomy, failure modes/causes/mechanisms, maintenance records, definitions behind MTBF/MTTR, data quality | Failure code groups (class / problem / cause / remedy) kept separate from reason/OEE codes; *functional failure* taxonomy for MTBF; MTTR only with active-repair evidence, otherwise "mean downtime to restore"; censored open repairs; coverage reported | §3.2, KPI07, KPI08, D13 | 1.3 (`failure_code_groups`), 2.7, 3.9 |
| **SMRP Best Practices metrics** | Standard definitions for availability, OEE, MTBF, MTTR, utilization | Metric names and denominators labelled explicitly (scheduled availability vs onstream factor vs OEE availability are different measures); reconciled OEE shown separately with its policy name | KPI04–KPI08 | 2.7 |
| **AVEVA PI Web API** (vendor API, E1) | Event frames, AF hierarchy, streams/streamsets, summaries, channels | Certified adapter with paging, open-frame sentinel handling, batch attribute reads, counter/rate semantics; installed help is the endpoint authority | PI01–PI09 | 1.6, 1.7 |
| **OASIS MQTT 5.0** (and 3.1.1 compatibility) (E3) | QoS levels, retained messages, session expiry, Last Will | QoS 1 default, persistent sessions, retained = state not transition, LWT → source health not equipment state, manual ack after durable append | MQ01–MQ05 | 1.8 |
| **Eclipse Sparkplug B** (optional) | MQTT payload spec: NBIRTH/NDEATH, aliases, sequence numbers | Optional certified decoder behind a capability flag | MQ05 | 1.8 |
| **Apache Kafka semantics** (E2) | Partition ordering, at-least-once, idempotent producers, consumer groups | Inbox/outbox with offset commit after durable write; keyed by tenant + source object; replication/ISR settings for production | KF01–KF05, FND02 | 1.5, 1.9 |
| **OPC UA / IEC 62541** (R2) | Node ids, source timestamps, status codes, subscriptions | R2 edge adapter mapping into the same envelope | §5.4 | R2.1 |
| **IEC 62443** (Industrial automation and control systems security) | Zones and conduits, least privilege, outbound-only integration zones | Plant-side collectors with outbound connections; no browser access to historians; no open proxy; TLS validation; read-only toward control; secrets by reference | §4.2, NFR01–NFR02 | 1.5, 1.6, 3.11 |
| **ISO 8601 / RFC 3339 + IANA tz database** | Timestamp interchange; timezone identifiers and DST rules | UTC `timestamptz` storage, ISO strings in APIs, IANA site timezones, stored UTC boundaries so later tz-rule updates don't reinterpret approved periods | §3.3, CAL01–CAL02 | 1.1, 2.1 |
| **OWASP ASVS** (reference for 3.11 security review) | Application security verification | Checklist for the security test summary | NFR01–NFR03 | 3.11 |

## Vendor conventions we preserve (not standards)
- **GE APM PLA impact codes** OTSD, OTDD, RMDD, RMSD, RPDD, RPSD, TADD — available as an optional tenant seed set; their presence is a vocabulary choice (§3.2).
- **GE reconciled OEE** (quantity-based, S2 p 35) — implemented as a separately labelled policy (KPI04).
- **Maximo daily production / PLR** status vocabulary (COMPLETED, RELEASED) — mapped to certified-input eligibility through site policy (ACT08).

## How "keep these in mind" is enforced in the plan
- Entity and column names follow ISO 22400 / ISO 14224 vocabulary where the spec does (`planned production time`, `availability loss`, `functional failure`, `active repair`).
- Every KPI response carries its policy name and denominator so a reader can map it to the ISO 22400 or SMRP definition it follows (API03, KPI04).
- Decision register items D03 (calendar/time model), D04 (OEE policy), D13 (failure taxonomy) are where the site chooses *which* interpretation of these standards applies; defaults follow ISO 22400 and ISO 14224 as described above.
