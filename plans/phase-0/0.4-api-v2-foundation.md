# 0.4 API v2 foundation — tenancy, guards, compound queries, errors, idempotency

**Status:** ⬜ not started · **Epic:** P0 E02 Contracts and tenancy · **Spec:** WF05, API01–API04, DB01, §13.2 roles, §2.3 G04 · **Tests:** T13 compound queries, T14 tenant attack · **Depends on:** 0.3

## Goal
Lay the API contract every later sub-phase builds on: tenant and scope resolved from identity (never from a query parameter), authorization on every route, AND-combined filters with cursor pagination, the standard error envelope, idempotent commands and ETag-protected updates. Fix the S1 query/security bugs in v1 so the current UI keeps working during the transition.

## Spec requirements covered
- WF05: roles and site/unit scope enforced in every API, job, export, download and realtime subscription; server resolves tenant from trusted identity; query parameter cannot elevate.
- API01: `/api/v2`; filters AND between dimensions, OR within; cursor pagination (default 100, max 500), stable secondary order by id, half-open windows, overlap semantics for intervals.
- API02: `Idempotency-Key` for creates/commands (24 h retention, 409 on reuse with different body); `If-Match` for revision-sensitive updates (412 on stale); 409 locked/invalid transition; 422 semantic validation; 401/403/429.
- API03: error body `{code, message, fieldErrors, correlationId, retryable}`; list body `{items, nextCursor, asOf, scope}`; analytical responses add `calculationRunId, policyVersion, dataQuality, coverage, isProvisional`; decimals as strings.
- API04: long-running operations return 202 + job id; job status counts reconcile.
- §13.2 role table; NFR01 "global code lists forbidden unless explicitly shared".
- G04 resolution: B1 B2 B14 B17 B18.

## Current implementation (verified)
- `JwtAuthGuard` applied per controller; **no `APP_GUARD`**; 6 controllers unguarded. `RolesGuard` used in 2 audit-log routes; `TenantGuard` exists, unused.
- JWT payload `{sub, email, role, tenantId, organizationId}`; roles: SuperAdmin, OrgAdmin, TenantAdmin, Manager, Analyst, Engineer, Operator. `JwtAuthGuard` throws a plain `Error` on failure (→ 500 not 401).
- `POST /auth/register` is `@Public` and accepts any role.
- `GET /production-events`: `tenantId > unitId > status > eventType > date` — one filter only (B1); `findByDateRange` uses `$gte/$lte` (B2). No pagination anywhere. `reasonCode`/`rca` relations stripped (B17). `unmapped-events` unguarded (B14). `CreateProductDto` rejects `tenantId/unitId` (B18).
- Global `ValidationPipe({whitelist, forbidNonWhitelisted, transform})`; `HttpExceptionFilter` returns `{statusCode, timestamp, path, method, message, error, stack}` — leaks stack traces (API03 forbids).
- `pi-proxy/request` forwards to any URL supplied by the client (§4.2 forbids unrestricted proxy).

## Target design
**Identity and scope**
- `RequestContext` (AsyncLocalStorage or request-scoped provider): `{ userId, tenantId, organizationId, roles[], siteIds[], unitIds[] | 'all', correlationId }` built by `JwtStrategy.validate` from the token + a `user_scopes` table (new: `user_id, scope_kind site|unit, scope_id, role`). SuperAdmin may **select** a tenant via header `X-Tenant-Id`, validated against membership; everyone else gets the token tenant. Query `tenantId` is ignored/rejected on v2 (400 if present and ≠ context).
- Global guards registered via `APP_GUARD`: `JwtAuthGuard` (with `@Public()` allowlist: login, refresh, health), `RolesGuard` (`@Roles()`), `ScopeGuard` (`@ScopeParam('unitId')` checks unit ∈ allowed scope). `JwtAuthGuard` throws `UnauthorizedException`.
- Repository helper `scoped(repo)` adds `tenant_id = :ctxTenant` to every v2 query; a test fails if a v2 entity query lacks it (SQL logger assertion in integration tests).
- `register` becomes admin-only (`@Roles('SuperAdmin','TenantAdmin')`) and cannot grant a role above the caller's; a one-time bootstrap path via CLI script replaces public SuperAdmin registration.

**v2 routing conventions**
- `src/v2/` folder with `V2Module`; controllers use `@Controller({ path: 'production-events', version: '2' })` with Nest URI versioning (`/api/v2/...`). v1 stays untouched except bug fixes.
- `ListQueryDto` base: `cursor`, `limit` (1–500, default 100), `sort` (allowlisted fields, always `+id` tiebreak), `from`, `to` (ISO, half-open). Interval filter semantics: `start < to AND (end IS NULL OR end > from)`.
- Array filters via repeated params (`unitIds=a&unitIds=b`) → OR within dimension; different params AND.
- `CursorCodec`: opaque base64 of `{sortValue, id}`; keyset pagination, never OFFSET.
- Response envelopes: `ListResponse<T> {items, nextCursor, asOf, scope}`; `AnalyticsResponse<T>` adds the API03 fields; `JobAccepted {jobId, statusUrl}`.
- Decimal fields serialized as strings via a `@DecimalString()` transformer.

**Errors**
- `ApiExceptionFilter` → `{code, message, fieldErrors?, correlationId, retryable}`; maps class-validator → 422 `VALIDATION_FAILED` with `fieldErrors`; 401 `UNAUTHENTICATED`; 403 `FORBIDDEN`; 404 `NOT_FOUND` (no existence leak across tenants: 404 not 403 for foreign ids); 409 `CONFLICT`/`INVALID_TRANSITION`/`IDEMPOTENCY_MISMATCH`; 412 `STALE_REVISION`; 429 with `Retry-After`. Stack traces only to logs. `correlationId` from `X-Correlation-Id` or generated; echoed in response header.

**Idempotency and concurrency**
- `idempotency_keys` table: `tenant_id, key, request_hash, response_status, response_body, created_at` (TTL 24 h cleanup job in worker). `@Idempotent()` decorator on POST commands: replay same key+hash → stored response; different hash → 409.
- `If-Match: "<row_version>"` on PATCH/PUT of revisioned resources; `ETag` on GET; `@VersionColumn` increments; mismatch → 412.
- Rate limiting: `@nestjs/throttler` global (per user) → 429.

**Fixes in v1 (so the current UI works until 3.x)**
- B1/B2: rewrite `GET /production-events` with a `ProductionEventQueryDto` and QueryBuilder (`Between`), AND-combined, add `planId`, `assetId`, `reasonCodeId`, `isOpen`, `page/pageSize`. Remove Mongo operators.
- B14: `JwtAuthGuard` on `unmapped-events`, `rca-recommendations`, `dashboard-configurations`, `uploads`; keep `health` public.
- B17: restore `reasonCode` and `rca` relations in event reads (Postgres has no column issue).
- B18: `CreateProductDto` accepts `tenantId`, `unitId`, `isActive`; `UpdateReconcileFormDto`/`UpdateLossCategoryDto`/`production-loss` DTOs = `PartialType(Create)` (B3 B4 B13 are listed under G05 but are one-line DTO fixes; do them here).
- `pi-proxy`: restrict `target` to the tenant's configured PI connection host; allowlisted paths/methods; TLS verification on by default with per-connection opt-out recorded.

## Tests
- **T13 compound queries** (integration): seed events across 2 tenants/3 units/2 reasons; query with tenant+unitIds+reasonIds+overlapping window; assert only matching rows, stable pagination across pages (no dupes/gaps when a row is inserted mid-pagination), limit bounds.
- **T14 tenant attack** (integration): tenant-B token requests tenant-A ids via path, filters, `X-Tenant-Id`, and later replay/export/socket (re-run in 3.11); expect 404/403 without existence leakage; audit row written.
- Idempotency: same key+body → identical response, one row; same key different body → 409; key expires after TTL.
- ETag: stale `If-Match` → 412; missing `If-Match` on revisioned PATCH → 428.
- Error envelope snapshot tests; no `stack` in body.
- v1 regression: `GET /production-events?tenantId&unitId&startDate&endDate` returns intersection; e2e `event-pull-and-rca.spec.ts` and `production.spec.ts` still pass.
- Guard coverage test: every controller route is either `@Public()` or guarded (generated from Nest route explorer).

## Definition of done
- All routes guarded by default; tenant never read from query on v2; v2 reference endpoint live with pagination; idempotency + ETag working; error envelope standard; B1 B2 B14 B17 B18 (and B3 B4 B13) closed with tests; T13 and T14 green; OpenAPI v2 snapshot in CI.

## Decisions / risks
- Users today have a single `tenantId`; multi-site scope (`user_scopes`) is new — default-populate one scope row per user for their tenant (all units).
- Changing `HttpExceptionFilter` shape may affect the frontend's `ApiError` parsing (`httpClient.ts` reads `body.message`); keep `message` string/array compatible.
- SSO/OIDC (NFR01) is deferred to 3.11; the `RequestContext` abstraction must not depend on the local JWT shape.
