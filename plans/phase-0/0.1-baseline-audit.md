## Target design
`plans/evidence/` folder, committed, containing:

| File | Content |
|---|---|
| `BASELINE.md` | Commit hash of the baseline commit made in step 1; stack versions (`node`, `npm`, Nest, TypeORM, pg, React, Vite); how servers were started; who verified |
| `routes-v1.txt` | Generated route inventory with guard flag (script `scripts/evidence/route-inventory.py`) |
| `schema-baseline.sql` | `pg_dump --schema-only` of `proact` |
| `data-inventory.md` | Row counts per table (`SELECT relname, n_live_tup FROM pg_stat_user_tables`) with a note on origin (seeded/demo/real) |
| `tests-baseline.md` | Output of `npm test` (backend), `npm run test:run` (frontend), `npm run test:e2e` with pass/fail counts |
| `s1-verification.md` | Table: finding ID → status (confirmed/resolved/absent/changed) → evidence (test name, request, or file:line) → target requirement (G01–G08) |
| `capability-demos.md` | For each "credited" capability in spec §2.2 (Event Hub, plans, Plan Dashboard, PLA, master data, PI, storage, RCA): what was demonstrated (screenshot/API transcript) and what is prototype-only |
| `source-samples/` | Representative PI event-frame JSON (from the PI server if reachable, else the shape from `pi-event-mapper.ts`), MQTT and Kafka sample payloads (placeholders until D09/D10) |

`test/fixtures/` (backend) containing one JSON per fixture `T01.json` … `T46.json` with `inputs`, `expected`, `spec_ref`, `tolerance` as given in §19. Integration/workflow tests (T04–T14, T22–T24, T33–T46) are written as scenario descriptions (Given/When/Then) in `test/fixtures/scenarios.md` and get executable form in their owning sub-phase.
